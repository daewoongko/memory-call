# 시연 영상 제작 계획 — 2분 20초

발표 6부(`docs/presentation_10min.md` 05:10–07:30)에서 재생하는 영상이다.
라이브 시연 진행표는 `docs/demo_script.md`에 그대로 남겨 두고, 이 문서는
**녹화본**을 어떻게 만들지만 다룬다.

---

## 1. 왜 라이브가 아니라 녹화인가

`docs/demo_script.md`의 "무너졌을 때" 표에 이미 답이 있다. 음성 인식 실패,
목소리 안 나옴, 응답 10초 지연, 전화 안 걸려옴, 흰 화면 — **여섯 가지 실패
모드가 이미 알려져 있다.** 10분 발표에서 그중 하나만 터져도 2분 30초가
4분이 되고, 뒤의 아키텍처와 클로징이 통째로 날아간다.

그리고 이 발표의 정점은 시연이 아니라 **4부(안전 정책)와 9부(클로징)**다.
시연은 4부에서 말한 것이 실제로 동작한다는 것만 증명하면 된다.

**라이브는 백업으로 준비해 둔다.** 심사위원이 요청하면 그때 켠다.
먼저 제안하지 않는다.

## 2. 화면 구성 — 두 화면을 반드시 동시에

이 서비스는 **양쪽이 같이 보여야 이해된다.** 어르신 화면만 보면 "AI 말벗"이고,
가족 화면만 보면 "알림 앱"이다. 둘을 동시에 보여줄 때만
"AI가 대신 받아서, 가족에게 넘긴다"가 읽힌다.

```
┌───────────────────────────────────────────────────────┐
│  00:42        AI가 대신 받는 중 · 무응답 25초           │  ← 상단 바
├───────────────────────┬───────────────────────────────┤
│                       │                               │
│      어르신 화면        │         가족 화면              │
│      (세로 폰)         │         (세로 폰)              │
│                       │                               │
│                       │                               │
├───────────────────────┴───────────────────────────────┤
│  "대웅아, 오늘 집에 오니?"                              │  ← 자막
└───────────────────────────────────────────────────────┘
```

**좌우 배치는 슬라이드 S12(사용자 플로우)와 같아야 한다.**
현재 S12는 왼쪽이 가족, 오른쪽이 어르신이다. 영상도 그렇게 하거나,
S12를 영상에 맞춰 뒤집는다. **둘 중 하나로 통일한다** — 청중이 5분 만에
좌우를 다시 학습하게 하면 안 된다.

### 상단 바 (항상 표시)

| 요소 | 내용 |
|---|---|
| 왼쪽 | 영상 내 경과 시간 |
| 가운데 | 현재 상태 라벨 — `전화 거는 중` `벨 울림 12초` `AI가 대신 받는 중` `안전 규칙 발동` `가족에게 알림 전송` |
| 오른쪽 | 화면 주인 표시 — `어르신` / `가족` |

상태 라벨은 **실제 앱 상태와 일치해야 한다.** 앱이 하지 않는 일을 라벨로
만들어 붙이면 그게 곧 조작이다.

### 자막 (필수)

- **소리 없이도 전부 이해되게 만든다.** 발표장 스피커는 믿을 수 없고,
  발표자가 영상 위에 말을 얹기 때문에 통화 음성이 잘 안 들린다
- 어르신 발화와 AI 발화를 **다른 색**으로 구분한다
- 자막은 화면 안에 구워 넣는다. 별도 자막 파일 금지

## 3. 컷 구성

`docs/demo_script.md`의 5막에서 **4막(복약)을 통째로 뺐다.** 2분 20초에
5막은 안 들어가고, 복약은 마지막 컷의 리포트 화면에 결과로 나타난다.
발표 대본도 복약을 리포트에서만 언급한다.

### 컷 1 — 연결되지 않는다, 그래서 AI가 받는다 (00:00–00:35)

| 시간 | 어르신 화면 | 가족 화면 | 상단 라벨 |
|---|---|---|---|
| 00:00 | 가족 얼굴 카드 4장 | 잠금 화면 / 다른 앱 | — |
| 00:03 | 손자 카드를 누른다 | 수신 화면이 뜬다 | `전화 거는 중` |
| 00:06 | 연결 상태 표시 | 벨 울리는 중, 받지 않음 | `벨 울림 6초` |
| 00:16 | `다소니와 먼저 이야기하기` 노출 | 그대로 | `벨 울림 16초` |
| 00:25 | AI 통화로 전환 | 수신 화면 사라짐 | `AI가 대신 받는 중 · 무응답` |
| 00:28 | 모핑 영상 시작 (8세 → 32세) | 대기 | — |

**여기서 보여줄 것**
- 가족 화면에 **실제로 벨이 울렸다**는 것. 이게 없으면 "15초 뒤에 시작하는
  AI 통화"와 구분되지 않는다
- 25초라는 대기가 **서버가 판정한 것**이라는 점. 하단에 작은 라벨로
  `takeover_reason: timeout`을 한 번 스쳐 보여주면 좋다

**주의** — 25초를 실시간으로 다 보여주면 지루하다. 06:00–00:16 구간을
2배속으로 압축하고, 화면에 `×2` 표시를 남긴다. **압축했다는 걸 숨기지 않는다.**

### 컷 2 — 거짓 약속을 하지 않는다 (00:35–01:20)

| 시간 | 내용 | 상단 라벨 |
|---|---|---|
| 00:35 | 어르신: "대웅아, 오늘 집에 오니?" | — |
| 00:40 | AI 응답 — 오늘 온다고 하지 않고 등록된 주말 방문만 이야기 | `안전 규칙 · 없는 약속 금지` |
| 00:52 | 오른쪽에 등록된 일정 카드를 오버레이로 잠깐 표시 | — |
| 01:00 | 어르신: "강릉 기차 여행 기억나니? 국수 먹었잖아" | — |
| 01:05 | AI가 맞장구치지 않고 되묻는다 | `확인되지 않은 기억` |
| 01:14 | 가족 화면 **확인 대기함**에 항목이 추가되는 순간 | `가족 확인 대기함에 추가` |

**이 컷이 영상 전체에서 제일 중요하다.** 45초를 쓴다.

**보여줄 것** — 00:52의 일정 카드 오버레이. AI가 왜 "주말"이라고 말할 수
있었는지가 눈으로 증명된다. 이게 "맥락은 등록된 사실에서만 나온다"의 시각화다.

**보여주지 말 것** — 일반 AI가 "응, 갈게"라고 답하는 비교 영상. 만들면 강력하지만
**우리 제품이 아닌 것을 우리가 연출한 것**이 된다. 이 발표에서 그건 자해다.
비교는 슬라이드 S9에서 말로만 한다.

### 컷 3 — 위험은 판단하지 않고 넘긴다 (01:20–01:45)

| 시간 | 내용 | 상단 라벨 |
|---|---|---|
| 01:20 | 어르신: "아까 화장실에서 넘어졌는데 일어나기가 힘들구나" | — |
| 01:24 | 어르신 화면 상단에 노란 띠 | `위험 신호 감지 · 낙상` |
| 01:26 | **가족 폰에 알림이 뜨는 순간** — 양쪽 동시 | `가족에게 알림 전송` |
| 01:33 | AI 응답 — 진단하지 않고 확인·안심 | — |
| 01:40 | 통화 종료 | — |

**01:26이 이 컷의 전부다.** 양쪽 화면에서 동시에 무언가 일어나는 유일한
순간이라 시각적으로도 가장 강하다. 여기서 0.5초 정지 프레임을 넣는다.

### 컷 4 — 가족은 무엇을 받는가 (01:45–02:20)

| 시간 | 내용 | 상단 라벨 |
|---|---|---|
| 01:45 | 가족 화면 전체로 전환 (분할 해제) | `가족` |
| 01:48 | 확인 대기함 — 강릉 기차 여행. `사실이에요` 를 누른다 | `승인해야 사실이 된다` |
| 01:58 | 통화 리포트 — 반복 질문 횟수, 복약 상태, 위험 신호 | — |
| 02:08 | 마음 기록층 — 어르신 원문 인용 | — |
| 02:14 | **안전 규칙이 응답을 고친 횟수** 항목에 정지 | `안전 규칙 발동 N회` |

02:14에서 정지한 채로 영상이 끝난다. 발표자가 이 화면을 배경으로
마지막 나레이션을 마치고 S14로 넘긴다.

**분할을 여기서 푸는 이유** — 통화가 끝난 뒤는 가족만의 시간이다.
화면 구성이 바뀌는 것 자체가 "국면이 바뀌었다"를 말해 준다.

## 4. 촬영 방식

### 하이브리드를 추천한다

| 구간 | 방식 | 이유 |
|---|---|---|
| 컷 1의 첫 5초 | **실사** — 손이 폰을 들고 가족 카드를 누르는 장면 | 사람이 쓰는 물건이라는 걸 한 번은 보여줘야 한다 |
| 나머지 전부 | **화면 캡처 합성** | 글자가 선명해야 리포트 숫자가 읽힌다 |

실사만 쓰면 리포트 화면의 숫자가 안 읽히고, 캡처만 쓰면 앱이 화면 속에만
사는 것처럼 보인다. 첫 5초의 실사가 나머지 2분 15초의 캡처를 현실에 묶는다.

### 화면 캡처

- 폰 두 대를 **동시에** 녹화한다. 따로 찍어서 붙이면 타이밍이 안 맞고,
  01:26의 동시 알림이 연출로 보인다
- Android는 내장 화면 녹화, iOS는 화면 기록. 해상도는 세로 1080 이상
- 녹화 전에 **알림 끄기, 방해 금지 모드, 배터리 100%, 시계 정상**
- 상단 상태바의 시계가 두 폰에서 같아야 한다. 다르면 합성이 티 난다

### 실사 5초

- 폰 화면이 반사되지 않는 각도. 창을 등지지 않는다
- 손만 나오게 한다. 얼굴이 나오면 그 사람의 동의가 필요해진다
- 배경은 정리된 실내. 병원처럼 보이는 배경은 피한다 — 이 서비스는
  의료 서비스가 아니다

### 편집

- 프레임: 30fps, 1920×1080 가로. 세로 폰 두 대를 좌우로 배치하면 딱 맞는다
- 음악: **넣지 않거나 아주 작게.** 발표자가 위에 말을 얹는다.
  음악이 감정을 대신 만들면 발표자 목소리가 죽는다
- 통화 음성은 남긴다. 단, 발표자가 말하는 구간에서 -12dB 정도로 낮춘다
  (덕킹). 대본의 `⏸` 구간에서만 원래 볼륨
- 컷 전환은 컷(cut)만. 디졸브·와이프 금지

## 5. 정직성 규칙

이 영상은 "확인되지 않은 것을 사실로 만들지 않는" 서비스의 시연이다.
영상 자체가 그 규칙을 어기면 발표 전체가 무너진다.

**허용**
- 대기 구간 배속 압축 — 단, 화면에 `×2` 표시
- 컷 사이의 이동 시간 잘라내기
- 자막·상태 라벨 추가 (실제 앱 상태와 일치할 것)
- 시나리오를 미리 정하고 여러 번 찍어서 잘 나온 테이크 쓰기

**금지**
- 앱이 실제로 하지 않는 UI를 합성으로 그려 넣기
- AI 응답 텍스트를 편집으로 바꾸기
- 실패한 응답을 잘라내고 성공한 것만 이어 붙여 **한 번에 된 것처럼** 보이기
- 경쟁 서비스의 나쁜 응답을 연출해 넣기
- 응답 지연을 잘라내 놓고 압축 표시를 안 하기

**애매하면 발표에서 한 줄 말한다.** "대기 구간은 배속을 걸었습니다."
이 한마디가 영상 전체의 신뢰를 만든다.

## 6. 준비와 백업

### 녹화 전

```bash
python tools/demo_reset.py --med-in 6    # 기록 초기화 + 일정 재설정
python tools/serve.py --no-reload
python tools/call_flow.py                # 호출 4가지 경로 확인
```

- [ ] 두 기기가 **같은 어르신**을 보고 **다른 역할**로 들어가 있는가
- [ ] `GET /api/devices` 로 서버가 어느 기기를 살아 있다고 보는지 확인
      (PC에 가족 탭이 열려 있으면 대기 시간이 안 줄어든다)
- [ ] 가족의 승인된 음성 ID와 아바타 ID가 생성돼 있는가
- [ ] HTTPS 주소(Render 또는 고정 Cloudflare Tunnel)로 접속했는가
- [ ] 개발자 도구를 닫았는가

### 녹화 후

- [ ] 소리를 끄고 처음부터 끝까지 재생 — 전부 이해되는가
- [ ] 발표장 뒤쪽 거리에서 리포트 숫자가 읽히는가
- [ ] 총 길이가 2분 20초 ±10초인가
- [ ] 개인 식별 정보(실제 전화번호, 실명, 주소)가 화면에 없는가
- [ ] 발표자가 영상 위에 나레이션을 얹어 **실제로 타이밍이 맞는지** 리허설

### 백업

| 위치 | 용도 |
|---|---|
| 슬라이드 내장 | 기본 재생 경로 |
| 노트북 로컬 파일 | 슬라이드가 깨졌을 때 |
| USB | 노트북이 안 될 때 |
| 라이브 시연 (`docs/demo_script.md`) | 요청받았을 때 |

**클라우드 링크 재생은 하지 않는다.** 발표장 네트워크를 믿지 않는다.

## 7. 시간이 부족하면 자르는 순서

2주 안에 완성해야 하고, 영상 제작은 마지막에 몰린다. 못 만들 상황이면
이 순서로 자른다.

1. **컷 4의 마음 기록층(02:08–02:14)** — 리포트 숫자만 남긴다
2. **컷 1의 실사 5초** — 전부 화면 캡처로
3. **컷 3(위험 감지)** — 슬라이드 스크린샷 한 장 + 말로 설명

**절대 자르지 않는 것 — 컷 2.** 거짓 약속을 하지 않는 장면이 없으면
이 발표에서 시연을 할 이유가 없다. 다른 걸 다 자르고 컷 2만 남겨서
40초짜리 영상을 틀어도 발표는 성립한다.
