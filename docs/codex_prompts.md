# Codex 작업 지시서 목록

담당자(요양원) 화면 재설계 작업을 세 갈래로 나눠 두었다.
**작업 순서대로 나열했다.** 서로 참조하므로 시작 전에 이 표를 먼저 본다.

| # | 문서 | 대상 | 상태 |
|---|---|---|---|
| 1 | `codex_prompt_dashboard.md` | 종합 현황 · 통화 리포트 | 작업 0·1 완료, 2·3 남음 |
| 2 | `codex_prompt_checklist.md` | **체크사항 탭 신설** | 미착수 |
| 3 | `codex_prompt_medication.md` | 일정·복약 탭 | 미착수 |

**2번을 3번보다 먼저 한다.** 체크사항 탭이 생기면서 일정·복약의 여정 A가
그쪽으로 옮겨가므로, 순서를 바꾸면 만들었다가 지우게 된다.

## 설계 근거 문서

| 문서 | 내용 |
|---|---|
| `analysis_design.md` | 관찰 분류 체계(8도메인 76신호)와 분석 설계. **15장 안전 문구 규칙은 모든 작업에 적용** |
| `mockups/medication_tab.html` | 세 화면 UI 목업. 1번째 화면은 체크사항, 2·3번째는 일정·복약 |

## 탭 역할 정리 (중복 방지)

| 탭 | 역할 |
|---|---|
| 종합 현황 | 오늘 무엇이 달랐나 — 관찰 요약과 우선순위 |
| 통화 리포트 | 통화에서 무엇을 알 수 있나 — 답변 유지 시간·시간 역행·정서 유발 주제 |
| **체크사항** | **무엇을 할지** — 모든 할 일의 단일 목록 |
| 일정·복약 | **어떻게 할지** — 체크리스트 실행, 증상 역조회, 약 정보, 달력 |

## 모든 작업의 공통 제약

- **새 테이블·새 신호 어휘를 만들지 않는다.** `analysis/observation_catalog.py`의
  76개 신호와 기존 테이블을 쓴다
- 숫자는 규칙이 만들고 문장만 LLM이 만든다 (CLAUDE.md)
- 진단·예측·원인 판정을 하지 않는다. **등록된 기준과 관찰의 대조까지만**
- 신호를 추가·수정하면 `tools/eval.py`를 돌린다
- 기존 테스트를 통과시킨다 (현재 190개)
- 접근성: 본문 대비 4.5:1, `DisplaySettings`의 글자 크기·명암 설정이 계속 동작
