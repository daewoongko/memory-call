# Codex 작업 지시서 목록

담당자(요양원) 화면 재설계. **작업 순서대로 나열했다.** 서로 참조하므로
시작 전에 이 문서를 먼저 읽는다.

## 사이드바 구조 (변경됨)

기존 2개(`분석 리포트` / `특이사항`)를 **3개**로 바꾼다.
기준은 **담당자가 그 화면에서 무엇을 하는가**다.

| 사이드바 | 하위 탭 | 하는 일 |
|---|---|---|
| **분석 리포트** | 종합 현황 · 통화 리포트 | **읽기** — 오늘 무엇이 달랐나 |
| **체크사항** | 체크리스트 · 일정·복약 | **하기** — 확인하고 기록한다 |
| **인계** | — | **넘기기** — 다음 근무자에게 |

바뀐 점 두 가지.

- `일정·복약`이 **분석 리포트에서 체크사항 아래로 이동**한다. 그것은 분석이
  아니라 실행 화면이다. 체크리스트에서 항목을 누르면 같은 메뉴 안에서
  실행 화면으로 넘어간다
- `특이사항`은 **`인계`로 바뀐다**. 지금의 특이사항은 세 화면과 전부 겹친다
  (위험 확인 버튼 → 체크사항, 관찰+근거 → 종합 현황, 조치 문구 → 확인 우선순위)

## 작업 순서

| # | 문서 | 대상 | 상태 |
|---|---|---|---|
| 1 | `codex_prompt_dashboard.md` | 종합 현황 · 통화 리포트 | 작업 0·1 완료, 2·3 남음 |
| 2 | `codex_prompt_checklist.md` | **체크사항 + 인계** | 미착수 |
| 3 | `codex_prompt_medication.md` | 일정·복약 | 미착수 |

**2번을 3번보다 먼저 한다.** 체크사항이 생기면서 일정·복약의 여정 A가
그쪽으로 옮겨가므로, 순서를 바꾸면 만들었다가 지우게 된다.

## 모든 작업의 공통 제약

- **새 테이블·새 신호 어휘를 만들지 않는다.** `analysis/observation_catalog.py`의
  76개 신호와 기존 테이블을 쓴다. 이번 작업의 신규 테이블은 `handovers` 하나뿐
- 숫자는 규칙이 만들고 문장만 LLM이 만든다 (CLAUDE.md)
- 진단·예측·원인 판정을 하지 않는다. **등록된 기준과 관찰의 대조까지만**
- 신호를 추가·수정하면 `tools/eval.py`를 돌린다
- 기존 테스트를 통과시킨다 (현재 190개)
- 접근성: 본문 대비 4.5:1, `DisplaySettings`의 글자 크기·명암 설정이 계속 동작
