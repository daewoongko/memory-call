# 관찰 분류 체계와 데이터 분석 설계

`backend/care.py`의 신호 분류와 `backend/report.py`의 집계를 "카운트 나열"에서
"근거 있는 관찰 분석"으로 바꾸기 위한 설계안이다. **아직 구현하지 않았다.**
무엇을 왜 바꾸는지 먼저 합의하기 위한 문서다.

**이 문서는 진단 도구를 만들자는 제안이 아니다.** 아래 모든 지표는 "등록된
사실과 실제 발화에서 관찰된 것"이며 상태를 판정하거나 예측하지 않는다.
CLAUDE.md의 안전 원칙은 그대로 유효하고, 분류가 늘어날수록 `eval.py`
시나리오를 먼저 늘린다는 순서도 그대로다.

## 문서 구성

| 부 | 내용 |
|---|---|
| I | **무엇을 관찰하나** — 8도메인 분류 체계 |
| II | **어떻게 측정하나** — 발화 구조, 약-관찰 연결, 통화 내 궤적, 복약, 안전 레이어, **통화 리포트 심층 지표** |
| III | **어떻게 판정하나** — 발생률 정규화, 관리도, 지속성, 동시발생, 침묵 |
| IV | **어떻게 보여주나** — 코호트 우선순위 화면 |
| V | **어떻게 검증하나** — 주입 테스트, 실데이터 |
| VI | **실행 순서** |

## 0. 지금 구조와 한계

| 층 | 현재 하는 일 | 한계 |
|---|---|---|
| 1층 `care.py` | 정규식 27신호 / 3도메인. LLM 제안 → 정규식 검증 | 도메인 구분이 임의적. 언어·실행기능 영역이 통째로 없음 |
| 2층 `report.py` 통화별 | `SequenceMatcher`로 반복 질문 묶기, 나머지는 카운트 | **순서를 버린다.** `aba`와 `abbbba`를 구분 못 함 |
| 3층 `report.py` 기간 | 2시간 블록 버킷팅, 직전 구간과 단순 차이 | 분모 없음. 노이즈와 변화를 구분 못 함 |

핵심 결함 두 가지:

1. **분모가 없다.** `_rhythm_window_stats`는 `signals["loneliness"]`를 그냥
   센다. 통화가 210건에서 250건으로 늘면 모든 신호가 같이 는다. 상태 변화와
   통화량 변화가 섞인다.
2. **"3건 늘었다"의 의미를 모른다.** 하루 32~41통(30일 1,090통) 도는
   데이터에서 주간 ±3건은 거의 확실히 우연이다. `_rhythm_change`는 1건
   차이에도 `"늘었습니다"`라고 단정한다.

세 번째로, **이미 DB에 있는데 안 쓰는 데이터가 많다.** II부의 상당 부분은
새 수집이 아니라 방치된 데이터를 연결하는 작업이다.

| 방치된 데이터 | 어디 있나 | II부 어디서 쓰나 |
|---|---|---|
| `monitoring_points`, `escalation_criteria` | `medications` | 3. 약-관찰 연결 |
| `status` 4종 (`DUPLICATE_SUSPECTED` 등) | `medication_logs` | 5. 복약 세분화 |
| `safety_flags`, `was_rewritten` | `utterances` | 6. 안전 레이어 통계 |
| 발화 순서(`seq`) | `utterances` | 2. 발화 구조 |
| `hallucination_report` 류 발화 | 분류 칸이 없어 폐기 | 1. 8도메인 |

# I부. 무엇을 관찰하나

## 1. 관찰 분류 체계 (3도메인 → 8도메인)

### 1.1 왜 바꾸나

현재 3도메인(`memory_orientation` / `emotion` / `daily_living`)은 구현
편의로 나뉘었고 임상 분류와 대응되지 않는다.

- **`memory_orientation`이 과적재됐다.** 지남력(지금 몇 시인가)과
  기억(어제 뭘 했나)은 임상적으로 다른 영역인데 한 칸에 있다.
- **언어와 실행기능이 통째로 빠졌다.** 단어 찾기 어려움, 에두르기, 순서
  있는 일 수행 곤란은 치매에서 가장 잘 알려진 관찰 항목인데 분류할 칸이
  없어 버려진다.
- **시드에 이미 있는 발화가 폐기된다.** 루이소체 환자(elder_002)의 환시
  호소, 혈관성 환자(elder_003)의 출혈 징후는 시드 템플릿에 들어 있는데
  받을 신호가 없다.

### 1.2 근거로 삼은 분류 체계

| 출처 | 무엇을 가져왔나 |
|---|---|
| DSM-5 신경인지영역 6개 | 복합주의·실행기능·학습기억·언어·지각운동·사회인지 → D2/D3/D4 골격 |
| NPI-12 (BPSD) | 망상·환각·초조/공격성·우울·불안·무감동·탈억제·과민성·수면·식욕 → D5/D6 골격 |
| MMSE 지남력 항목 | 시간·장소·사람 → D1 |
| Katz ADL / Lawton IADL | 식사·복약·위생·금전관리 → D7, D4 일부 |
| 연결발화(connected speech) 지표 연구 | 어휘다양성·대명사 과다·내용어 비율·보속증 → D3, 2층 계산 지표 |

**전화 통화로 관찰 가능한 것만 남겼다.** DSM-5의 지각운동, NPI의 이상
운동행동(배회·서성임)·식욕 변화는 신체 관찰이 필요하므로 제외하거나
"환자가 직접 말한 경우"로만 좁혔다.

### 1.5 3계층 산출 방식 (중요)

신호를 80개로 늘리면서 전부 정규식으로 가면 실패한다. CLAUDE.md에 이미
`"아버지"`가 `"할아버지"` 안에 있어서 규칙이 무력화된 사례가 있다. 80개면 그
위험이 곱해진다. 그래서 **신호마다 산출 방식을 명시한다.**

| 계층 | 방식 | 개수(안) | 신뢰도 |
|---|---|---|---|
| Tier A | 정규식 직접 검증 | ~55 | 높음. 그대로 기록 |
| Tier B | 텍스트 통계 계산 | ~12 | 높음. 값 자체가 근거 |
| Tier C | LLM 제안 + 인용 검증 | ~10 | 낮음. **후보로만**, 보호자 확인 전까지 리포트 확정 금지 |

Tier B가 핵심이다. `pronoun_overuse`는 키워드가 아니라 **비율**이다.
정규식으로 잡을 수 없고 잡아서도 안 된다.

### 1.6 정규식 확장 시 반드시 같이 넣을 것

- **부정 문맥 가드**: `"약을 안 먹었다"`(사실 진술)와 `"약 먹었나?"`(혼동)를
  구분한다. 현재 `DIRECT_SIGNAL_PATTERNS`에 이 구분이 없다.
- **신호당 eval 시나리오 최소 2개** (양성 1 + 음성 1).
- **부분 문자열 충돌 테스트**: 신호 추가 시 기존 패턴과 겹치는지 자동 검사.

# II부. 어떻게 측정하나

## 2. 발화 구조와 말투 변화 (2층)

### 2.1 지금 무엇을 놓치나

`_group_repeats`는 발화를 유사도로 묶고 **개수만** 센다. 순서를 버린다.

```
발화 순서:  a  b  a          →  현재 출력: a 2회, b 1회
발화 순서:  a  b b b b  a     →  현재 출력: a 2회, b 4회
```

두 경우가 임상적으로 완전히 다른데 리포트에는 "반복 질문 N회"로 똑같이 나온다.

- `a b a` = **산발적 반복**. 다른 얘기를 하다 다시 돌아옴 → 단기기억
- `a b b b b a` = **연속 고착(보속증)** → 실행기능

### 2.2 발화 시퀀스 인코딩

기존 `SequenceMatcher` 클러스터링을 재사용하되 **순서를 보존한다.**

1. 한 통화의 어르신 발화를 `seq` 순으로 나열
2. 유사도 기준으로 클러스터 ID 부여 → `"abbbba"`
3. 시퀀스에서 지표 계산

| 지표 | 계산 | 임상적 의미 |
|---|---|---|
| `max_run_length` | 최대 연속 반복 (`abbbba`→4) | 보속증. 실행기능 |
| `immediate_repeat_ratio` | 인접 쌍 중 같은 클러스터 비율 | 고착 정도 |
| `sequence_entropy` | 클러스터 분포 섀넌 엔트로피 | 낮으면 같은 말만 반복 |
| `distinct_ratio` | 고유 클러스터 수 ÷ 발화 수 | 화제 다양성 |
| `return_turns` | 같은 클러스터 재등장까지 턴 수 | **짧아지면 단기기억 저하** |

`return_turns` 감소와 `max_run_length` 증가는 **다른 현상**이고, 분리해서
보고해야 다른 대응을 할 수 있다.

> 초 단위 재등장 간격(`return_seconds`)은 넣지 않는다. `created_at`이 DB
> 기록 시각이라 STT·네트워크 지연이 섞인다. 턴 수는 그런 오염이 없다.

### 2.3 언어 지표 (Tier B)

형태소 분석기 없이 계산 가능한 것만 골랐다. **1차는 어절 기반 근사**로
시작하고 필요하면 나중에 교체한다.

| 지표 | 계산 | 주의 |
|---|---|---|
| `mattr` | 이동평균 어휘다양성(창 50어절) | 단순 TTR은 길이에 좌우되므로 **MATTR을 쓴다** |
| `pronoun_ratio` | 지시대명사(그거/저거/이거/거시기…) ÷ 전체 어절 | 단어 찾기 어려움의 대리지표 |
| `content_word_ratio` | 내용어 추정 ÷ 전체 어절 | 어절 기반이라 근사값 |
| `mean_utterance_length` | 발화당 평균 어절 수 | |
| `filler_rate` | 채움말(음/어/그…) 빈도 | **채택 전 STT 보존 여부 측정 필수** |
| `incomplete_ratio` | 종결어미 없이 끝난 발화 비율 | 위와 같음 |

> **STT 의존성 경고.** 브라우저 Web Speech API는 필러·머뭇거림을 제거하고
> 문장을 정리해서 내보낸다. `filler_rate`와 `incomplete_ratio`는 STT가
> 원본을 얼마나 보존하는지 **먼저 측정한 뒤** 채택을 정한다. 보존하지 않으면
> 이 두 지표는 버린다.

### 2.4 저장 위치

`reports`에 `speech_metrics TEXT`(JSON) 컬럼 추가. `care_summary`와 분리하는
이유: `care_summary`는 근거 인용이 붙는 개별 관찰이고, `speech_metrics`는
통화 전체의 수치다. 성격이 다르다.

## 3. 약–관찰 자동 연결 ★

### 3.1 지금 상황

`medications` 테이블에 관찰 기준이 **이미 등록돼 있다.**

```
클로피도그렐 75mg  (elder_003)
  indication:           "뇌경색 재발 예방을 위한 항혈소판 치료"
  monitoring_points:    ["멍·코피·잇몸 출혈", "검은 변·혈뇨", "낙상 후 출혈"]
  escalation_criteria:  "멈추지 않는 출혈, 검은 변, 혈뇨 또는 머리를 부딪힌
                         낙상은 즉시 의료진·응급 절차로 보고"
  review_interval_days: 7
```

그런데 **이 텍스트가 관찰 신호와 전혀 연결되어 있지 않다.** D8의
`bleeding_signal`이 관찰돼도 시스템은 이 어르신이 항혈소판제를 복용 중이며
그것이 이 약의 보고 기준에 해당한다는 사실을 모른다.

### 3.2 설계

약별 `monitoring_points` / `escalation_criteria` ↔ D7·D8 신호 매핑 테이블을
만든다. 매핑은 **자동 추론이 아니라 등록**이다. 약을 등록할 때 담당자가
관찰 항목을 고르거나, 시드에서는 미리 지정한다.

```
schedule_id                 signal                  tier
med_jeongho_clopidogrel     bleeding_signal         escalation   ← 즉시 보고
med_jeongho_clopidogrel     injury_report           escalation
med_sunja_rivastigmine      dizziness               monitoring   ← 경과 관찰
med_sunja_rivastigmine      appetite_change         monitoring
med_sunja_levodopa          hallucination_report    escalation
med_sunja_levodopa          fall_reported           escalation
```

### 3.3 출력

```
⚠ 이정호 어르신 — 등록된 보고 기준에 해당하는 발화가 관찰되었습니다
   약: 클로피도그렐 75mg (뇌경색 재발 예방)
   보고 기준: "멈추지 않는 출혈, 검은 변, 혈뇨"
   관찰: "잇몸에서 피가 자꾸 난다"  (오늘 09:14, utterance-1842)
   → 처방 의료진 당일 보고 대상
```

### 3.4 왜 안전한가

**진단도 예측도 아니다.** 담당자가 등록해 둔 관찰 기준과, 환자가 실제로 한
말을 대조할 뿐이다. 시스템은 "이 약을 바꿔라"라고 말하지 않는다 —
CLAUDE.md 규칙 5(복약 지시 금지)를 건드리지 않는다. `review_interval_days`가
지난 약은 "검토 주기 도래"로 표시만 한다.

## 4. 통화 내 궤적

### 4.1 왜 필요한가

지금 리포트는 전부 "어르신 상태가 어떤가"만 말한다. **"우리가 무엇을
했는가"를 보여주는 내부 지표가 하나도 없다.** 이 서비스가 도움이 되는지
알 방법이 없다.

### 4.2 설계

한 통화의 발화를 위치로 나누고(전반부/후반부, 또는 3등분) 정서 신호 비율을
비교한다.

```
불안·초조 신호가 관찰된 통화 42건
  통화 전반부:  32건 (76%)
  통화 후반부:   9건 (21%)
```

### 4.3 해석 제약 (반드시 지킬 것)

**인과 주장 금지.** 다음 편향이 확실히 존재한다.

- **선택 편향**: 어르신은 불안할 때 전화를 건다. 시간이 지나면 자연히
  가라앉는 부분이 섞인다(평균 회귀)
- **관찰 편향**: 통화 후반에는 발화 수 자체가 줄어들 수 있다 →
  **반드시 발화 수로 정규화**한다

허용 문구: `"통화 후반부에 관찰 빈도가 낮았습니다"`
금지 문구: `"통화가 진정에 도움이 되었습니다"`

발표에서도 "효과"가 아니라 "관찰된 분포"로 말한다.

## 5. 복약 데이터 세분화

### 5.1 지금 상황

`medication_logs.status`는 4종류인데 지금은 `USER_CONFIRMED` vs 나머지로
이분된다.

```python
confirmed = sum(1 for log in med_logs if log["status"] == "USER_CONFIRMED")
unclear   = sum(1 for log in med_logs
                if log["status"] in ("UNCLEAR", "REFUSED", "DUPLICATE_SUSPECTED"))
```

- **`DUPLICATE_SUSPECTED`(중복 복용 위험)는 안전 이슈인데 "needs_check"에
  묻힌다.**
- **`REFUSED`(거부)는 완전히 다른 문제(BPSD)인데 같이 묻힌다.**

### 5.2 설계

- 4상태를 끝까지 분리해서 집계·표시한다
- **약별(`schedule_id`) × 요일 × 시간대** 교차표를 만든다

교차하면 `"저녁 약만 계속 놓친다"`, `"주말에 아침 약 확인이 안 된다"` 같은
패턴이 보인다. 지금은 안 보인다. `medication_by_schedule`에 이미 약별 집계가
있으므로 축만 추가하면 된다.

### 5.3 `medication_reviews` 연결

`medication_reviews`(severity 0~3, observed_flags)가 스키마에 있는데 리포트에
쓰이지 않는다. 3장의 약-관찰 연결과 묶어 "이 약의 관찰 항목에서 이번 주
관찰된 것"으로 표시한다.

## 6. 안전 레이어 작동 통계

### 6.1 왜 필요한가

CLAUDE.md는 **"차별점은 아바타 기술이 아니라 안전 정책"**이라고 못박았다.
그런데 그 안전 정책이 실제로 몇 번 작동했는지 보여주는 화면이 없다.

`utterances.safety_flags`와 `was_rewritten`이 매 발화 저장되고 있는데
리포트에서 한 번도 읽지 않는다.

### 6.2 설계

이건 **환자 분석이 아니라 시스템 신뢰성 지표**다. 별도 화면/탭으로 분리한다.

| 지표 | 내용 |
|---|---|
| 규칙별 발동 횟수 | 8개 규칙 중 무엇이 몇 번 |
| 재작성률 | `was_rewritten` ÷ 전체 AI 발화 |
| 유발 발화 | 어떤 환자 발화가 위반 직전까지 몰고 갔나 |
| eval 통과율 추이 | `tools/eval.py` 결과의 시계열 |

### 6.3 발표에서의 쓰임

> "거짓 약속 방지 규칙이 이 기간에 14회 작동했고, 그중 11회가
> '오늘 집에 오니?' 계열 발화였습니다."

데모 시나리오의 핵심 장면(거짓 약속 방지)이 **일회성 연출이 아니라 상시
작동하는 장치**임을 수치로 보여준다.

## 7. 통화 리포트 심층 지표 ★

`통화 리포트` 화면이 답해야 할 질문은 "몇 번 그랬나"가 아니라 **"어떻게
달라지고 있나"**다. 아래 세 지표는 전부 기존 데이터에서 나오며, 횟수를
의미로 바꾼다.

> **적용 범위: `통화 리포트` 탭만.** `종합 현황` 탭은 이 장의 대상이 아니다.
>
> `WeekdayTimeHeatmap`은 현재 두 탭에 모두 렌더된다
> (`ReportTabs.jsx:559`, `:571`). 같은 컴포넌트지만 역할이 다르다.
>
> | 탭 | 역할 | 처리 |
> |---|---|---|
> | 종합 현황 | `onSelectDate`가 붙은 **날짜 선택 도구** | **유지** |
> | 통화 리포트 | "집중 구간을 확인하세요" — **분석으로 제시** | **제거**, 7.1~7.3으로 교체 |
>
> 통화 리포트에서 제거하는 이유: 통화량은 환자 상태가 아니라 전화 거는 습관을
> 재는 지표라 담당자가 할 일이 나오지 않고, 시드가 만든 패턴이라 발표에서
> 방어하기도 어렵다. 날짜를 고르는 UI로 쓰는 것은 별개이며 그대로 둔다.
>
> 통화 리포트의 시간축은 8.1의 분모를 적용한
> **시간대별 신호 발생률**(`sundowning_signal`) 하나로만 남긴다.

### 7.1 답변 유지 시간 — 재질문까지 걸린 간격

지금 리포트는 `"반복 질문 6회"`라고만 말한다. 그런데 임상적으로 중요한 것은
횟수가 아니라 **답을 듣고 얼마 만에 다시 묻는가**다. 같은 6회라도
9분 간격과 40분 간격은 전혀 다른 상태다.

```
8월 3일   "지금 몇 시냐"  → 재질문까지  38분
8월 8일                                21분
8월 12일                                9분
```

**계산**

2.2의 발화 클러스터를 재사용한다. 한 통화 안에서 같은 클러스터가 연속
등장할 때의 간격을 모은다.

| 지표 | 정의 |
|---|---|
| `retention_seconds` | 같은 클러스터 재등장까지 경과 초의 **중앙값** |
| `retention_turns` | 같은 간격을 턴 수로 |
| 일별 값 | 그날 모든 통화의 간격을 모아 중앙값 |

**제약**

- **통화 경계를 넘지 않는다.** 통화 사이 6시간 공백은 "6시간 만에 잊었다"가
  아니다. 간격은 한 통화 안에서만 센다
- 한 통화에서 같은 클러스터가 2회 이상 나와야 간격이 하나 생긴다
- 간격 표본이 최소 개수에 못 미치는 날은 **판정하지 않는다**(8.4)
- `created_at`은 DB 기록 시각이라 초 단위 정밀도는 신뢰할 수 없다.
  다만 9분과 38분을 가르는 데는 충분하다. **분 단위로만 표시한다**
- **방향 주의**: 짧아지는 것이 우려 방향이다. 관리도를 걸 때 하한 이탈을
  본다. 문구는 `"짧아지고 있습니다"`이며 `"나빠지고 있습니다"`가 아니다

### 7.2 시간 역행 지점 — 어느 시기를 말씀하시는가

지남력 혼동을 지금은 `시간 혼동 10회`로만 센다. **어디로 돌아가는지**가
훨씬 실용적인 정보다.

```
"회사 늦었다, 출근해야지"   → 직장기
"애들 밥 줘야 하는데"        → 육아기
"학교 가야 한다"             → 학령기
```

가족에게 즉시 쓸모가 있다. 어르신이 지금 육아기에 계시면 그 시절 기준으로
대화하는 편이 억지로 현재로 끌어오는 것보다 안정적이다.

**계산**

`past_role_confusion`에서 **생활 시기 범주**를 추출한다.

| 범주 | 표현 예 |
|---|---|
| `school_age` 학령기 | 학교 가야, 수업, 선생님, 숙제 |
| `young_adult` 청년기 | 군대, 입대, 시집·장가 |
| `working` 직장기 | 회사, 출근, 사무실, 공장, 일 나가야 |
| `child_rearing` 육아기 | 애들 밥, 학교 보내야, 우리 애 |
| `recent` 근래 | 등록된 최근 사건 |

**절대 나이를 추정하지 않는다.** `"45세로 돌아가셨습니다"`는 근거 없는 단언이며
규칙 2 위반이다. 시스템은 **범주만** 기록한다. 보호자가
`elder_profiles.life_stages`(JSON)에 각 범주의 실제 연대를 등록한 경우에만
연도를 함께 보여준다. 미등록이면 범주 이름만 쓴다.

**표시**

범주는 순서가 있으므로(학령기 → 청년기 → 직장기 → 육아기 → 근래)
**순서형 색조 하나**로 그린다. 범주형 팔레트를 쓰지 않는다.
30일에 걸쳐 분포가 더 이른 시기로 이동하는지를 함께 본다.

**문구 제약**: `"퇴행"`, `"악화"` 금지. `"언급된 생활 시기"`, `"이 시기의
표현이 늘었습니다"`까지만.

### 7.3 정서 유발 주제 — 무엇 다음에 불안이 오는가

어떤 화제가 나온 **직후에** 정서 신호가 따라오는지 본다.

```
"통장·돈" 언급 후   → 불신·불안이 이어진 경우  8 / 11회   lift 3.1
가족 이름 언급 후    → 외로움이 이어진 경우      5 / 23회   lift 1.4
```

**계산**

9장의 lift를 **방향이 있는 인접 관계**로 좁혀 쓴다. 정서 신호가 나온 발화의
직전 1~2턴에서 주제 표지를 찾는다.

```
lift = P(정서 | 직전에 주제 등장) / P(정서)
```

날짜 단위 상관이 아니라 **통화 안 인접 턴**이라 표본이 수백 개다.
30일 데이터로도 통계적으로 성립한다.

**등록값과 대조한다**

`elder_profiles.anxiety_triggers`에 보호자가 등록해 둔 유발 요인이 있는데
지금 분석에 전혀 쓰이지 않는다. 등록된 것과 관찰된 것을 나란히 놓으면
**등록되지 않은 새 유발 요인**을 찾을 수 있다.

| | 등록됨 | 관찰됨 |
|---|---|---|
| 돈·통장 | O | O (lift 3.1) |
| 병원 | O | 관찰 안 됨 |
| 가족 이름 | **미등록** | O (lift 1.4) ← 확인 필요 |

**제약**

- **인과 금지.** `"돈 얘기가 불안을 유발합니다"`가 아니라
  `"돈 얘기 뒤에 불안 표현이 함께 관찰되었습니다"`
- 최소 동시발생 횟수 게이트(예: 5회 미만 미표시)
- 상위 5개만 표시

# III부. 어떻게 판정하나

## 8. 노이즈와 변화 구분

네 단계를 **순서대로** 적용한다. 앞 단계 없이 뒤 단계만 하면 의미가 없다.

### 8.1 발생률 정규화 (선행 필수)

| 대상 | 분모 | 표기 |
|---|---|---|
| 관찰 신호 | 어르신 발화 수 | "발화 100건당 N회" |
| 반복 질문 | 통화 수 | "통화당 N회" |
| 위험 이벤트 | 통화 수 | "통화 100건당 N회" |

손댈 곳: `_window`, `_rhythm_window_stats`, `_delta`, `_rhythm_change`.

### 8.2 개인 베이스라인 관리도 (SPC)

그 사람 **자신의** 과거 N일로 기준선을 만들고 이탈을 판정한다.

- 카운트 데이터이므로 포아송 기반: `λ̂` = 과거 N일 평균 발생률,
  관리한계 = `λ̂ ± 2√λ̂`
- 다른 환자와 비교하지 않는다
- 표현은 **"평소 범위를 벗어났습니다"** — 관찰 서술이지 진단이 아니다.
  `"악화되었습니다"`는 금지

의료 질 관리의 표준 기법이라 발표에서 근거를 댈 수 있다.

### 8.3 지속성 판정

하루 튄 값은 올리지 않는다. **3일 연속 관리한계 이탈** 또는 CUSUM 누적합
임계 초과(완만한 변화용). 알림 피로 방지가 실제 제품 가치다.

### 8.4 최소 표본 게이트

통화 수가 적은 날·시간대는 판정하지 않고 **"표본 부족"**으로 표시한다.
현재 `_rhythm_analysis`의 `ready` 게이트 개념을 모든 지표로 확장한다.

### 8.5 추세 검정

일별 중앙값 시계열에 **Mann-Kendall 추세검정**을 적용한다.

- 비모수라 정규분포 가정 없음, 소표본(n=14~30)에서 동작
- numpy만으로 구현 가능
- **"추세가 관찰되지 않았습니다"를 말할 수 있다.** 지금처럼 무조건
  "늘었습니다"라고 하지 않는다

> **응답 지연 분석은 하지 않는다.** `utterances.latency_ms`는 LLM 응답
> 시간이고, `TurnRequest`는 `text`만 받는다. 어르신 응답 지연은 측정 자체가
> 안 되며, 프론트·API·스키마 3곳을 고쳐도 STT·네트워크가 섞여 신뢰할 수 없다.

## 9. 신호 동시발생

### 9.1 왜 필요한가

지금은 신호를 각각 센다. 그런데 임상적으로는 **조합**이 훨씬 중요하다.
`"외로움 12건"`보다 `"외로움과 반복질문이 함께 나온 통화 8건, 모두 오후"`가
훨씬 행동 가능한 정보다.

### 9.2 설계

통화 단위 동시발생 행렬 + lift.

```
lift(A,B) = P(A ∩ B) / (P(A) × P(B))
```

lift > 1이면 우연보다 자주 함께 나타난다는 뜻.

```
동시 관찰 (기간 내)
  복약 혼동 + 시간 혼동    lift 3.4   동시 18통화   → 중복 복용 위험
  환시 + 두려움            lift 2.8   동시 12통화   → 루이소체 전형
  외로움 + 반복 질문       lift 2.1   동시  8통화   → 정서가 원인 가능성
```

1,090통화가 있어 통계적으로 성립한다.

### 9.3 제약

- **인과 아님.** 문구는 `"함께 관찰되었습니다"`까지만
- 최소 동시발생 횟수 게이트(예: 5회 미만은 표시 안 함)
- 표시 개수 상한(상위 5쌍). 28×28 행렬을 다 보여주면 아무도 안 본다

### 9.4 `sundowning_signal` 은 여기서 나온다

1.4에서 유보한 `sundowning_signal`은 **시간블록 × D6 초조 신호**의
동시발생으로 정의한다. 별도 정규식이 아니다.

## 10. 침묵 감지 (통화 빈도의 이상 탐지)

### 10.1 왜 필요한가

지금 통화 없는 시간은 `"이 시간에는 통화가 없었습니다"`로만 표시된다.
그런데 **매일 오후에 전화하던 분이 이틀 연속 안 하면 그 자체가 신호다.**
낙상해서 못 하는 것일 수도 있다.

놓쳤을 때 가장 위험한 케이스인데 지금 탐지 장치가 전혀 없다.

### 10.2 설계

8.2의 관리도를 신호가 아니라 **통화 수**에 그대로 적용한다.
기법 재사용이라 추가 비용이 거의 없다.

- 일별 통화 수 관리도 → 하한 이탈 탐지
- 시간블록별 통화 수 관리도 → "평소 이 시간에 하던 연락이 없음"

### 10.3 제약

- 정상 사유(외출, 가족 방문, 병원)가 흔하다 → **경보가 아니라 확인 항목**으로
- 방문 일정(`schedules`)이 등록돼 있으면 그날은 제외
- 서비스 자체가 멈춘 경우(서버 장애)와 구분해야 한다 → 전체 환자가 동시에
  조용하면 시스템 문제로 판단하고 개인 신호로 올리지 않는다

## 11. 코호트 우선순위 화면

### 11.1 지금 상황

`CareManagerScreen.jsx`에서 요양사는 어르신 목록에서 한 명을 고른다.
그 목록에 있는 정보는 **이름·진단명·호실뿐**이다.

```
[박순자]  루이소체 치매·파킨슨증   요양원 2층 생활실  ›
[이정호]  혈관성 치매·고혈압       요양원 3층 생활실  ›
```

오늘 누구를 먼저 봐야 하는지에 대한 정보가 0이다. 한 명씩 눌러봐야 한다.
환자가 20명이면 성립하지 않는다.

### 11.2 설계

목록을 **우선순위 큐**로 바꾼다.

```
오늘 확인 우선순위
1. 박순자   두려움 ↑ 평소 범위 밖 (3일 연속)     z=3.2   근거 8건
   └ 클로피도그렐 보고 기준 해당 발화 1건            ← 3장
2. 고길동   복약 혼동 ↑ 평소 범위 밖 (2일)       z=1.8   근거 5건
3. 이정호   평소 범위 안                          z=0.4
4. 김말순   평소 오후 연락이 이틀째 없음          ← 10장
   ─────────
   코호트 기준선 미확립 (n=3) — 환자 간 절대 비교는 하지 않습니다
```

### 11.3 정렬 기준: 절대값이 아니라 z-score

**환자 간 절대 건수 비교는 금지한다.** 말이 많은 사람이 항상 나빠 보인다.
통화량·성격·질환이 다르다.

대신 각자 8.2의 z-score로 정렬한다.

- 의미: "누가 더 나쁜가"가 아니라 **"누가 평소와 가장 다른가"**
- n이 작아도 성립한다. 각자의 기준선이 각자 안에서 나오기 때문

우선순위 가중치는 **약-관찰 escalation(3장) > 안전 신호(D8) > z-score**
순으로 둔다. 통계적 이탈보다 등록된 보고 기준 해당이 먼저다.

### 11.4 코호트 통계는 만들지 않는다

환자가 3명이다. 백분위·군집·유형 분류는 통계적으로 무의미하다. 화면에
**"코호트 기준선 미확립(n=3)"**을 명시하고 인원이 쌓이면 활성화되는 자리로
비워 둔다. 없는 것을 있는 척하지 않는다.

## 12. 실제 데이터 확보 가능성

조사 결과 **2주 안에 실환자 데이터로 검증하는 것은 불가능하다.**

| 데이터셋 | 내용 | 접근 조건 | 판정 |
|---|---|---|---|
| AI Hub **인지기능 장애 진단 음성/대화** | 치매·인지장애 환자 + 정상 대조군 실제 음성 | IRB 심의결과 통지서 + IRB 승인 연구계획서 + 소속 증빙. **오프라인 안심존**(다운로드 불가, 격리 시설 방문 분석) | **불가.** 서류만 수 주 |
| AI Hub **자유대화 음성(노인남여)** | 60세 이상 자유대화 + 전사 + 메타데이터 | **휴대폰 인증만** | **가능.** 치매 라벨 없음 |
| **DementiaBank** Pitt Corpus | AD 약 200명 + 대조군 100명, 종단 데이터 | 무료. DUA + IRB 준수 서약 | 조건부. 영어. 지도교수 경유 시 가능성 |

**AI Hub 노인 자유대화**는 치매 라벨이 없어도 쓸모가 있다. 2.3의 언어 지표를
**정상 노인의 분포**로 계산해 두면 "우리 지표가 실제 한국 노인 발화에서 어떤
범위를 갖는지"를 말할 수 있다. 진단 기준이 아니라 **척도 감각**이다.

**DementiaBank**는 한국어가 아니라 정규식은 못 쓰지만 2.2~2.3의 **구조 지표는
언어 독립적**이다. 신청은 지금 걸어두고 발표 후 검증으로 돌린다.

## 13. 주입 테스트 ★

실데이터보다 **발표에서 더 강력하다.**

1. 시드 생성기와 분석기를 완전히 분리한다
2. 시드에 **없던 패턴**을 인위적으로 주입한다
   - 예: 15일차부터 `max_run_length`를 하루 0.2씩 증가
   - 예: 20일차부터 `return_turns`를 30% 단축
   - 예: 특정일에 `bleeding_signal` 1건 주입 (3장 연결 확인)
   - 예: 이틀간 오후 통화를 0으로 (9장 침묵 감지 확인)
   - **대조군: 아무것도 바꾸지 않은 구간** (위양성 확인용)
3. 분석기가 **며칠째에 탐지하는지** 측정한다
4. 결과를 지표로 발표한다
   - **탐지 지연**: "주입 후 평균 N일 만에 탐지"
   - **위양성률**: "변화 없는 대조 구간에서 M% 오탐"

이러면 `"우리 시스템이 패턴을 발견했습니다"`(검증 불가, 질문 한 번에 무너짐)
대신 **"이 지표는 이렇게 계산되고, 이 정도 크기의 변화를 N일 안에, 오탐
M%로 탐지합니다"**라고 말할 수 있다. 합성 데이터라는 사실을 숨기지 않으면서
성능을 정량화하는 방법이다.

# VI부. 실행 순서

의존 관계가 있어 순서를 바꾸면 앞 작업이 헛돈다.

### Phase 0 — 기반
- 0-1. `eval.py`에 신호별 양성/음성 시나리오 골격
- 0-2. **발생률 정규화**(8.1). 모든 카운트에 분모 도입
- 0-3. 시드 생성기 ↔ 분석기 분리 확인
- 0-4. STT 필러 보존 여부 측정 → 2.3 지표 채택 결정

### Phase 1 — 분류 체계
- 1-1. **8도메인 스키마 정의 + 기존 27신호 재매핑** (스키마 변경이라 선행)

### Phase 2 — 이미 있는 데이터 연결 (노력 대비 효과 최상)
- 2-1. **약–관찰 매핑 테이블 + 연결 로직** (3장)
- 2-2. 복약 4상태 세분화 + 약별×요일×시간대 교차 (5장)

### Phase 5 — 통화 리포트 심층 지표 (7장) ★

- 7-1. **주입 테스트 하네스** (13장)

### 순서를 이렇게 잡은 이유

- **Phase 2를 앞으로 뺐다.** 약-관찰 연결과 복약 세분화는 새 통계 기법이
  아니라 **이미 등록된 데이터를 안 쓰던 것**을 고치는 작업이다. 노력 대비
  효과가 가장 크고, 요양사에게 즉시 행동 가능한 유일한 정보다.
- **Phase 4는 Phase 0-2(정규화)에 의존한다.** 분모 없이 관리도를 얹으면
  통화량 변동을 상태 변화로 오판한다.
- **Phase 5는 Phase 3·4의 재사용이다.** 답변 유지 시간은 Phase 3의 클러스터를,
  정서 유발 주제는 Phase 4-4의 lift를 그대로 쓴다. 새 기법이 아니라 기존
  계산을 다른 축으로 돌리는 것이라 앞선 두 Phase 없이는 만들 수 없다.
  시간 역행(5-2)만 독립적이라 먼저 해도 된다.
- **Phase 7은 Phase 4에 의존한다.** 주입 테스트는 "관리도가 며칠째 울리는가"를
  재는 것이라 관리도가 없으면 잴 대상이 없다.
- **Phase 8은 마지막.** 화면은 앞의 모든 값이 나온 뒤에 붙인다.
