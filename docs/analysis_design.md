# 통화 근거 기반 분석 계약

보호자 리포트는 진단 점수표가 아니라 실제 어르신 발화에서 확인된 관찰을
정리하는 화면입니다. 모든 수치와 문장은 다시 원문 근거로 내려갈 수 있어야 합니다.

## 1. 데이터 흐름

```text
어르신 원문 발화
  → LLM이 관찰 후보와 근거 문구 제안
  → care.normalize가 서버 신호 목록·정규식·원문 포함 여부로 검증
  → 통화별 care_summary와 실제 utterance_id 저장
  → report가 일별·시간대별·기간별로 집계
  → 보호자 화면에서 수치와 근거 발화를 함께 표시
```

LLM이 제안했다는 이유만으로 관찰이 확정되지는 않습니다. `backend/care.py`가
근거 문장이 실제 어르신 발화에 포함되는지, 해당 신호의 서버 규칙과 맞는지 다시
검사합니다.

## 2. 8개 관찰 영역

기준 목록은 `backend/analysis/observation_catalog.py`의 `DOMAIN_LABELS`입니다.

| 영역 | 통화에서 다루는 예 |
|---|---|
| 지남력 | 날짜·시간·장소·사람 혼동 표현 |
| 기억 | 최근 사건 불확실, 같은 질문 반복 |
| 언어 | 단어 찾기 어려움, 말의 흐름 변화 |
| 실행기능·판단 | 행동 순서·결정·금전 판단 확인 필요 |
| 정서 | 불안, 외로움, 그리움 표현 |
| 행동·초조 | 초조, 분노, 불신, 배회 의도 표현 |
| 일상생활 수행 | 식사·수분·물건 위치·생활 행동 어려움 |
| 안전·신체 | 어지럼, 넘어짐, 통증 등 직접 말한 신호 |

이 영역은 통화로 관찰 가능한 발화 분류일 뿐 질환의 중증도나 의학적 상태를
의미하지 않습니다.

## 3. 신호 등급

`SignalSpec.tier`는 확정 방법을 제한합니다.

- A: 서버 정규식이 어르신 원문에서 직접 찾은 신호
- B: 반복 간격·비율처럼 서버가 계산한 통계. LLM이 생성할 수 없음
- C: 정규식만으로 확정하지 않고 사람 확인이 필요한 후보

부정 문맥도 따로 검사합니다. 예를 들어 “약을 안 먹었다”와 “약을 먹었나?”는 같은
단어가 있어도 서로 다른 관찰입니다.

## 4. 리포트 수치

### 오늘과 최근 30일

레이더 차트는 각 영역의 오늘 관찰 건수와 최근 기록의 하루 평균을 비교합니다.
축은 화면에 함께 보이는 값 중 최댓값에 맞춰 공통으로 스케일하며, 모든 축에 같은
임의 점수를 넣지 않습니다. 라벨에 `오늘 N · 평균 M` 원값을 표시합니다.

최근 평균은 다음과 같습니다.

```text
영역의 기간 내 관찰 건수 / 실제 관찰 일수
```

데이터가 없는 영역은 0입니다. 기록 일수가 적을 때는 진단적 의미를 부여하지
않습니다.

### 기간 비교

서로 다른 통화량을 그대로 비교하지 않도록 `backend/analysis/rates.py`가 분모를
포함한 값을 계산합니다.

- 관찰: 어르신 발화 100개당 건수
- 반복 질문: 통화 1건당 건수
- 위험: 통화 100건당 건수

비교에는 최소 표본이 필요합니다.

- 통화 비교: 각 기간 10통 이상
- 발화 비교: 각 기간 어르신 발화 20개 이상

표본이 부족하면 “기록이 충분하지 않습니다”라고 표시합니다. 차이가 있어도
“관찰 빈도의 차이이며 상태 악화나 호전을 의미하지 않는다”는 문구를 유지합니다.

## 5. 근거 보존

- 위험, 미확인 회상, 안전 규칙 작동, 관찰 신호는 모두 원본 `utterance_id` 또는
  `call_event` ID를 가집니다.
- 리포트 생성 LLM이 존재하지 않는 근거 ID를 반환하면
  `report._verify_evidence()`가 제거합니다.
- 보호자 인용문은 LLM의 요약문이 아니라 저장된 어르신 발화에서 가져옵니다.
- 확인되지 않은 이야기는 `unverified` 목록에만 있고, 확인 추억과 그림일기의
  사실 근거로 사용하지 않습니다.

## 6. 확인 우선순위

화면 우선순위는 의료 판단이 아니라 보호자가 무엇을 먼저 직접 확인할지 정리한
목록입니다.

1. 아직 확인하지 않은 안전 발화
2. 최근 하루 평균보다 늘어난 식사·시간 혼동 등 생활 신호
3. 같은 수준 또는 감소한 신호

각 항목은 발생 시각, 실제 발화, 가족이 확인할 행동을 함께 보여줍니다. 데이터가
없으면 평온하다고 단정하지 않고 “관찰 없음”으로 취급합니다.

## 7. 그림일기와 마음 기록

- 그림일기는 승인된 통화 발화와 `memory_id`가 연결된 경우에만 사실 기반 기록으로
  노출합니다.
- 통화에서 처음 나온 장면을 그린 이미지는 가족 확인 전에는 상상 이미지로
  구분합니다.
- 사랑·그리움 같은 마음 기록은 직접 표현을 인용하며, 한 번 나온 모호한 발화를
  더 강한 감정 문장으로 바꾸지 않습니다.

- 핵심 테스트: `tests/test_analysis_foundation.py`, `tests/test_report_care.py`,
