# 관찰 분류 체계와 데이터 분석 설계

이 문서는 `backend/care.py`의 신호 분류와 `backend/report.py`의 집계를
"카운트 나열"에서 "근거 있는 관찰 분석"으로 바꾸기 위한 설계안이다.
아직 구현하지 않았다. 무엇을 왜 바꾸는지 먼저 합의하기 위한 문서다.

**이 문서는 진단 도구를 만들자는 제안이 아니다.** 아래 모든 지표는
"등록된 사실과 실제 발화에서 관찰된 것"이며, 상태를 판정하거나 예측하지
않는다. CLAUDE.md의 안전 원칙은 그대로 유효하며, 분류가 늘어날수록
`eval.py` 시나리오를 먼저 늘린다는 순서도 그대로다.

---

## 0. 지금 구조와 한계 요약

| 층 | 현재 하는 일 | 한계 |
|---|---|---|
| 1층 `care.py` | 정규식 27신호 / 3도메인. LLM 제안 → 정규식 검증 | 도메인 구분이 임의적. 언어·실행기능 영역이 통째로 없음 |
| 2층 `report.py` 통화별 | `SequenceMatcher`로 반복 질문 묶기, 나머지는 카운트 | **순서를 버린다.** `aba`와 `abbbba`를 구분 못 함 |
| 3층 `report.py` 기간 | 2시간 블록 버킷팅, 직전 구간과 단순 차이 | 분모 없음. 노이즈와 변화를 구분 못 함 |

핵심 결함 두 가지:

1. **분모가 없다.** `_rhythm_window_stats`는 `signals["loneliness"]`를 그냥
   센다. 통화가 210건에서 250건으로 늘면 모든 신호가 같이 는다. 상태 변화와
   통화량 변화가 섞인다.
2. **"3건 늘었다"의 의미를 모른다.** 하루 32~41통(30일 1,090통) 도는
   데이터에서 주간 ±3건은 거의 확실히 우연이다. `_rhythm_change`는 1건
   차이에도 `"늘었습니다"`라고 단정한다.

## 1. 관찰 분류 체계 재설계 (3도메인 → 8도메인)

### 1.1 왜 바꾸나

현재 3도메인(`memory_orientation` / `emotion` / `daily_living`)은 구현
편의로 나뉘었고 임상 분류와 대응되지 않는다. 그래서 두 가지 문제가 있다.

- **`memory_orientation`이 과적재됐다.** 지남력(지금 몇 시인가)과
  기억(어제 뭘 했나)은 임상적으로 다른 영역인데 한 칸에 들어 있다.
- **언어와 실행기능이 통째로 빠졌다.** 단어 찾기 어려움, 에두르기, 순서
  있는 일 수행 곤란은 치매에서 가장 잘 알려진 관찰 항목인데 분류할 칸이
  없어서 버려지고 있다.

### 1.2 근거로 삼은 분류 체계

| 출처 | 무엇을 가져왔나 |
|---|---|
| DSM-5 신경인지영역 6개 | 복합주의·실행기능·학습기억·언어·지각운동·사회인지 → D2/D3/D4 골격 |
| NPI-12 (BPSD) | 망상·환각·초조/공격성·우울·불안·무감동·탈억제·과민성·수면·식욕 → D5/D6 골격 |
| MMSE 지남력 항목 | 시간·장소·사람 → D1 |
| Katz ADL / Lawton IADL | 식사·복약·위생·금전관리 → D7, D4 일부 |
| 연결발화(connected speech) 지표 연구 | 어휘다양성·대명사 과다·내용어 비율·보속증 → D3, 2층 계산 지표 |

**전화 통화로 관찰 가능한 것만 남겼다.** DSM-5의 지각운동, NPI의 이상
운동행동(배회·서성임)·식욕 변화는 신체 관찰이 필요하므로 제외하거나
"환자가 직접 말한 경우"로만 좁혔다.

### 1.3 제안하는 8개 도메인

| ID | 도메인 | 근거 | 신호 수(안) |
|---|---|---|---|
| D1 | 지남력 | MMSE 지남력 | 9 |
| D2 | 기억 | DSM-5 학습·기억 | 7 |
| D3 | **언어** ★신규 | DSM-5 언어 + 연결발화 연구 | 9 |
| D4 | **실행기능·판단** ★신규 | DSM-5 실행기능 + Lawton IADL | 7 |
| D5 | 정서 | NPI 우울/불안/무감동 | 9 |
| D6 | **행동·초조** ★분리 | NPI 초조/망상/탈억제 | 10 |
| D7 | 일상생활 수행 | Katz ADL / Lawton IADL | 12 |
| D8 | **안전·신체** ★분리 | 위험 에스컬레이션 | 10 |

별도 트랙: **관계·정서 자산**(`meaningful_moments`)은 임상 관찰이 아니라
가족에게 전할 가치가 있는 표현이므로 8도메인과 분리해 유지한다.

### 1.4 신호 목록 (안)

`*` 표시는 2층에서 계산되는 지표(정규식 아님). `†` 표시는 LLM 제안 +
보호자 확인이 필요한 후보(자동 확정 금지).

**D1 지남력**
`time_confusion` 시간 혼동 / `date_confusion` 날짜·계절 혼동 /
`place_confusion` 장소 혼동 / `place_displacement` 집에 가야 한다는 호소 /
`person_confusion` 사람 혼동 / `person_misidentification` 다른 사람으로 착각 /
`situation_confusion` 상황 혼동 / `past_role_confusion` 과거 역할로 되돌아감 /

> `deceased_alive_reference`는 CLAUDE.md 규칙 4(prohibited 기억)와 직접
> 맞물린다. 관찰로 기록하되 AI가 먼저 꺼내지 않는 정책은 그대로다.

**D2 기억**
`recent_event_confusion` 최근 사건 혼동 / `repeated_question`* 반복 질문 /

`confabulation_suspect`† 앞뒤 안 맞는 회상

**D3 언어** ★신규
`word_finding_difficulty` 단어 찾기 어려움("그… 뭐지") /

**D4 실행기능·판단** ★신규

### 1.5 3계층 산출 방식 (중요)

신호를 80개로 늘리면서 전부 정규식으로 가면 실패한다. CLAUDE.md에 이미
`"아버지"`가 `"할아버지"` 안에 있어서 규칙이 무력화된 사례가 기록돼 있다.
80개면 그 위험이 곱해진다. 그래서 **신호마다 산출 방식을 명시한다.**

| 계층 | 방식 | 개수(안) | 신뢰도 |
|---|---|---|---|
| Tier A | 정규식 직접 검증 | ~55 | 높음. 그대로 기록 |
| Tier B | 텍스트 통계 계산 | ~12 | 높음. 값 자체가 근거 |
| Tier C | LLM 제안 + 인용 검증 | ~10 | 낮음. **후보로만**, 보호자 확인 전까지 리포트 확정 금지 |

Tier B가 이번 설계의 핵심이다. `pronoun_overuse`는 키워드가 아니라
**비율**이다. 정규식으로 잡을 수 없고 잡아서도 안 된다.

### 1.6 정규식 확장 시 반드시 같이 넣을 것

- **부정 문맥 가드**: `"약을 안 먹었다"`(사실 진술)와 `"약 먹었나?"`(혼동)를
  구분한다. 현재 `DIRECT_SIGNAL_PATTERNS`에 이 구분이 없다.
- **신호당 eval 시나리오 최소 1개(양성) + 1개(음성)**. CLAUDE.md 원칙
  "기능보다 eval 시나리오를 먼저 넣는다"를 그대로 적용한다.
- **부분 문자열 충돌 테스트**: 신호를 추가할 때 기존 신호와 패턴이
  겹치는지 자동 검사.

## 2. 2층 강화 — 발화 구조와 말투 변화

### 2.1 지금 무엇을 놓치고 있나

`_group_repeats`는 발화를 유사도로 묶고 **개수만** 센다. 순서를 버린다.

```
발화 순서:  a  b  a        →  현재 출력: a 2회, b 1회
발화 순서:  a  b b b b  a   →  현재 출력: a 2회, b 4회
```

두 경우가 임상적으로 완전히 다른데 리포트에는 "반복 질문 N회"로 똑같이
나온다.

- `a b a` = **산발적 반복**. 다른 얘기를 하다 다시 돌아옴 → 단기기억
- `a b b b b a` = **연속 고착(보속증, perseveration)** → 실행기능

지금은 이 둘을 구분할 방법이 없다.

### 2.2 발화 시퀀스 인코딩

기존 `SequenceMatcher` 클러스터링을 재사용하되 **순서를 보존한다.**

1. 한 통화의 어르신 발화를 `seq` 순으로 나열
2. 기존 유사도 기준으로 클러스터 ID 부여 → `"abbbba"`
3. 시퀀스에서 지표 계산

| 지표 | 계산 | 임상적 의미 |
|---|---|---|
| `max_run_length` | 최대 연속 반복 (`abbbba`→4) | 보속증. 실행기능 |
| `immediate_repeat_ratio` | 인접 쌍 중 같은 클러스터 비율 | 고착 정도 |
| `sequence_entropy` | 클러스터 분포 섀넌 엔트로피 | 낮으면 같은 말만 반복 |
| `distinct_ratio` | 고유 클러스터 수 ÷ 발화 수 | 화제 다양성 |
| `return_turns` | 같은 클러스터 재등장까지 턴 수 | **짧아지면 단기기억 저하** |
| `return_seconds` | 같은 클러스터 재등장까지 실제 초 | 위와 같음, 시간 축 |

`return_turns` 감소와 `max_run_length` 증가는 **다른 현상**이고, 분리해서
보고해야 보호자·요양사가 다른 대응을 할 수 있다.

### 2.3 언어 지표 (Tier B)

연결발화 연구에서 쓰는 지표 중 한국어 형태소 분석기 없이 계산 가능한 것만
골랐다. 형태소 분석기(konlpy 등)를 추가하면 정밀도가 오르지만 의존성이
늘어난다 — **1차에는 어절 기반 근사로 시작**하고 필요하면 나중에 교체한다.

| 지표 | 계산 | 주의 |
|---|---|---|
| `mattr` | 이동평균 어휘다양성(창 50어절) | 단순 TTR은 길이에 좌우되므로 **MATTR을 쓴다** |
| `pronoun_ratio` | 지시대명사(그거/저거/이거/거시기…) ÷ 전체 어절 | 단어 찾기 어려움의 대리지표 |
| `content_word_ratio` | 내용어 추정 ÷ 전체 어절 | 어절 기반이라 근사값 |
| `mean_utterance_length` | 발화당 평균 어절 수 | |
| `filler_rate` | 채움말(음/어/그…) 빈도 | STT가 필러를 지우면 무의미 → **먼저 확인 필요** |
| `incomplete_ratio` | 종결어미 없이 끝난 발화 비율 | |

> **STT 의존성 경고.** 브라우저 Web Speech API는 필러·머뭇거림을 자동으로
> 제거하고 문장을 정리해서 내보낸다. `filler_rate`와
> `incomplete_ratio`는 **STT가 원본을 얼마나 보존하는지 먼저 측정한 뒤**
> 채택 여부를 정해야 한다. 보존하지 않으면 이 두 지표는 버린다.

### 2.4 저장 위치

`reports` 테이블에 `speech_metrics TEXT`(JSON) 컬럼을 추가한다.
`care_summary`와 분리하는 이유: `care_summary`는 근거 인용이 붙는
개별 관찰이고, `speech_metrics`는 통화 전체의 수치다. 성격이 다르다.

## 3. 3층 강화 — 시간과 추세

### 3.1 지금 확인된 제약 (중요)

- `utterances.latency_ms`는 **LLM 응답 시간**이다. 어르신 응답 시간이 아니다.
- `TurnRequest`는 `text`만 받는다. 프론트가 타이밍을 보내지 않는다.
- `utterances.created_at`은 DB 기록 시각이라 STT·네트워크·LLM 지연이 섞인다.

**즉 어르신 응답 지연은 오늘 측정 자체가 불가능하다.** 하려면
프론트(`useSpeech.js`는 이미 `emitSpeechTiming`으로 타이밍을 만들고 있다)
→ `TurnRequest` → `utterances` 스키마까지 3곳을 바꿔야 한다.

측정하더라도 **절대값은 쓰지 말고 같은 사람 내 추세로만** 써야 한다.
기기·네트워크가 바뀌면 값이 통째로 흔들린다.

### 3.2 추가할 시간 지표

| 지표 | 오늘 가능? | 비고 |
|---|---|---|
| 통화 지속시간 추세 | 가능 | `calls.duration_sec` |
| 통화당 턴 수 추세 | 가능 | `utterances` 카운트 |
| 발화 길이 추세 | 가능 | 2.3의 `mean_utterance_length` 일별 중앙값 |
| 반복 질문 재발 간격 | 가능 | 2.2의 `return_seconds` |
| **어르신 응답 지연** | **불가** | 스키마·API·프론트 변경 필요 |
| 일몰 시간대 초조 | 가능 | 시간블록 × D6 신호 교차 |

### 3.3 추세 판정

일별 중앙값 시계열에 **Mann-Kendall 추세검정**을 쓴다.

- 비모수라 정규분포 가정이 없다
- 소표본(n=14~30)에서 동작한다
- numpy만으로 구현 가능 (scipy 불필요)
- 출력이 "증가/감소/추세 없음 + p값"이라 **"추세가 관찰되지 않았습니다"를
  말할 수 있다.** 지금처럼 무조건 "늘었습니다"라고 하지 않는다

## 4. 노이즈와 변화 구분

네 단계를 순서대로 적용한다. 앞 단계 없이 뒤 단계만 하면 의미가 없다.

### 4.1 발생률 정규화 (선행 필수)

모든 신호 카운트에 분모를 붙인다.

| 대상 | 분모 | 표기 |
|---|---|---|
| 관찰 신호 | 어르신 발화 수 | "발화 100건당 N회" |
| 반복 질문 | 통화 수 | "통화당 N회" |
| 위험 이벤트 | 통화 수 | "통화 100건당 N회" |

손댈 곳: `_window`, `_rhythm_window_stats`, `_delta`, `_rhythm_change`.

### 4.2 개인 베이스라인 관리도 (SPC)

그 사람 **자신의** 과거 N일로 기준선을 만들고 이탈을 판정한다.

- 카운트 데이터이므로 포아송 기반: `λ̂` = 과거 N일 평균 발생률,
  관리한계 = `λ̂ ± 2√λ̂`
- 다른 환자와 비교하지 않는다
- 표현은 **"평소 범위를 벗어났습니다"** — 관찰 서술이지 진단이 아니다.
  `"악화되었습니다"`는 여전히 금지

의료 질 관리에서 표준으로 쓰는 방법이라 발표에서 근거를 댈 수 있다.

### 4.3 지속성 판정

하루 튄 값은 올리지 않는다.

- **3일 연속 관리한계 이탈**, 또는
- CUSUM 누적합이 임계 초과 (완만한 변화 탐지용)

알림 피로 방지가 실제 제품 가치다. 매일 "늘었다/줄었다"를 뱉으면
보호자가 곧 무시한다.

### 4.4 최소 표본 게이트

통화 수가 적은 날·시간대는 **판정하지 않고 "표본 부족"으로 표시**한다.
현재 `_rhythm_analysis`에 `ready: len(observed_days) >= 7 and total_calls >= 30`
게이트가 이미 있다. 이 개념을 모든 지표로 확장한다.

## 5. 전체(코호트) 비교

### 5.1 절대값 비교는 금지

요양사 화면에서 환자 A와 B의 신호 건수를 나란히 놓으면 안 된다.
말이 많은 사람이 항상 나빠 보인다. 통화량·성격·질환이 다르다.

### 5.2 비교 가능한 것: 자기 대비 이탈 정도

각자 4.2의 z-score를 계산한 뒤 **그 z-score로 정렬**한다.

- 의미: "누가 더 나쁜가"가 아니라 **"누가 평소와 가장 다른가"**
- n이 작아도 성립한다. 각자의 기준선이 각자 안에서 나오기 때문
- 요양사 화면의 기본 정렬은 "오늘 확인 우선순위 큐"가 된다

### 5.3 코호트 통계는 아직 만들지 않는다

지금 환자가 3명이다. 백분위·군집·유형 분류는 통계적으로 무의미하다.
화면에는 **"코호트 기준선 미확립(n=3)"**을 명시하고, 인원이 쌓이면
활성화되는 자리로 비워 둔다. 없는 것을 있는 척하지 않는다.

## 6. 실제 데이터 확보 가능성

조사 결과, **2주 안에 실환자 데이터로 검증하는 것은 불가능하다.**

| 데이터셋 | 내용 | 접근 조건 | 판정 |
|---|---|---|---|
| AI Hub **인지기능 장애 진단 음성/대화** | 치매·인지장애 환자 + 정상 대조군 실제 음성 | IRB 심의결과 통지서 + IRB 승인 연구계획서 + 소속 증빙. **오프라인 안심존**(다운로드 불가, 격리 시설 방문 분석) | **불가.** 서류만 수 주 |
| AI Hub **자유대화 음성(노인남여)** | 60세 이상 자유대화 + 전사 + 메타데이터 | **휴대폰 인증만** | **가능.** 치매 라벨은 없음 |
| **DementiaBank** Pitt Corpus | AD 약 200명 + 대조군 100명, 종단 데이터 | 무료. DUA + IRB 준수 서약, 연구 목적 등록 | 조건부. 영어. 지도교수 경유 시 가능성 |

### 6.1 현실적인 활용안

**AI Hub 노인 자유대화**는 치매 라벨이 없지만 쓸모가 있다.
2.3의 언어 지표(MATTR, 대명사 비율, 발화 길이)를 **정상 노인의 분포**로
계산해 두면, "우리 지표가 실제 한국 노인 발화에서 어떤 범위를 갖는지"를
말할 수 있다. 진단 기준이 아니라 **척도 감각**을 얻는 용도다.

**DementiaBank**는 한국어가 아니라 정규식은 못 쓰지만, 2.2~2.3의
**구조 지표는 언어 독립적**이다. 알고리즘이 실제 치매 발화에서 대조군과
다른 값을 내는지 확인하는 용도로는 쓸 수 있다. 신청은 지금 걸어두고
발표 후 검증으로 돌리는 것을 권한다.

### 6.2 그래서 2주 안에 할 정직한 검증: 주입 테스트

이게 실데이터보다 **발표에서 더 강력하다.**

1. 시드 생성기와 분석기를 완전히 분리한다
2. 시드에 **없던 패턴**을 인위적으로 주입한다
   - 예: 15일차부터 `max_run_length`를 하루 0.2씩 증가
   - 예: 20일차부터 `return_turns`를 30% 단축
   - 예: 아무것도 바꾸지 않은 대조군(위양성 확인용)
3. 분석기가 **며칠째에 탐지하는지** 측정한다
4. 결과를 지표로 발표한다
   - **탐지 지연**: "주입 후 평균 N일 만에 탐지"
   - **위양성률**: "변화 없는 대조 구간에서 M% 오탐"

이러면 "우리 시스템이 패턴을 발견했습니다"(검증 불가, 질문 한 번에 무너짐)
대신 **"이 지표는 이렇게 계산되고, 이 정도 크기의 변화를 N일 안에,
오탐 M%로 탐지합니다"**라고 말할 수 있다. 합성 데이터라는 사실을 숨기지
않으면서도 시스템의 성능을 정량화하는 방법이다.

## 7. 실행 순서

의존 관계가 있어서 순서를 바꾸면 앞 작업이 헛돈다.

### Phase 0 — 기반 (이것 없이는 나머지가 무의미)
- 0-1. `eval.py`에 신호별 양성/음성 시나리오 골격 추가
- 0-2. **발생률 정규화**(4.1). 모든 카운트에 분모 도입
- 0-3. 시드 생성기 ↔ 분석기 분리 확인

### Phase 1 — 분류 체계
- 1-a. **8도메인 스키마 정의 + 기존 27신호 재매핑** (빠름, 스키마 변경이라 선행 필요)
- 1-b. Tier A 신호 확장 + 부정 문맥 가드 (점진적, 시간 나는 대로)
- 1-c. `safety.py`의 위험 탐지와 D8 통합 (중복 정의 제거)

### Phase 2 — 발화 구조 ★핵심
- 2-1. 발화 시퀀스 인코딩 + run-length 지표 (2.2)
- 2-2. 언어 지표 (2.3). **STT 필러 보존 여부 먼저 측정**
- 2-3. `reports.speech_metrics` 컬럼 추가 및 노출

### Phase 3 — 시계열
- 3-1. 개인 베이스라인 관리도 (4.2)
- 3-2. 지속성 판정 (4.3)
- 3-3. Mann-Kendall 추세 (3.3)
- 3-4. (선택) 어르신 응답 지연 측정 — 3곳 변경 필요

### Phase 4 — 검증
- 4-1. **주입 테스트 하네스** (6.2)
- 4-2. 탐지 지연·위양성률 측정 및 문서화

### Phase 5 — 코호트 화면
- 5-1. z-score 기반 우선순위 큐 (5.2)
- 5-2. 요양사 화면 반영

### 시간이 부족하면

**Phase 0 → 2 → 3-1/3-2 → 4** 만 해도 성격이 바뀐다.
Phase 1-b(신호 80개 확장)는 노동량 대비 발표 임팩트가 가장 낮다.
Phase 2와 4가 가장 강력하다 — `aba`/`abbbba` 구분은 설명하기 쉽고
직관적이며, 주입 테스트는 정량적 근거를 준다.
