# Codex 작업 지시 — `체크사항` 신설 · `특이사항` → `인계`

담당자 사이드바를 다시 짠다. 기준은 **담당자가 그 화면에서 무엇을 하는가**다.

```
분석 리포트   → [종합 현황 | 통화 리포트]     읽기
체크사항      → [체크리스트 | 일정·복약]      하기      7/12
인계                                          넘기기
```

- `일정·복약`을 분석 리포트에서 **체크사항 아래로 옮긴다.** 분석이 아니라
  실행 화면이다. 체크리스트에서 항목을 누르면 같은 메뉴 안에서 실행 화면으로
  넘어간다
- `특이사항`을 **`인계`로 바꾼다.** 지금의 특이사항은 세 화면과 전부 겹친다
  (위험 확인 버튼 → 체크사항, 관찰+근거 → 종합 현황, 조치 문구 → 확인 우선순위)

`종합 현황`의 `SafetyChecklist`(`ReportTabs.jsx:384`)를 체크사항으로 옮기고
투두 리스트로 다시 만든다.

**체크사항과 인계는 화면을 나눈다.** 데이터는 같지만 여는 빈도가 다르다 —
체크는 근무 중 수십 번, 인계는 근무당 두 번(출근에 읽고 퇴근에 쓴다).
합치면 체크 하나 하려고 인계 패널을 스크롤해 지나가야 해서 체크리스트가
느려진다.

---

## 0. 먼저 고칠 것 — 체크 상태가 브라우저에만 있다

```js
const key = `care-safety-checks:${elderId}:${date}`;
localStorage.setItem(key, JSON.stringify(next));
```

요양원은 **교대 근무**가 전제인데 이 구조로는

- 야간 근무자가 주간 근무자의 확인 상태를 **볼 수 없다**
- 태블릿을 바꾸면 사라진다
- 누가 언제 확인했는지 기록이 없다

`"확인했다고 생각했는데 안 되어 있음"`이 발생하는 구조다. 지금 체크리스트의
마지막 항목이 `"확인 결과를 근무 인계에 기록"`인데 정작 그 체크 자체가
인계되지 않는다.

**서버 저장이 이 작업의 선행 조건이다.**

---

## 1. 새 테이블을 만들지 않는다

항목과 완료 기록은 **이미 세 곳에 있다.**

| 항목 | 어디서 오나 | 완료를 어디에 쓰나 |
|---|---|---|
| 복약 확인 | `medications.scheduled_time` | `medication_logs` |
| 관찰 주기 도래 | `medications.review_interval_days` | `medication_reviews` |
| 위험 신호 확인 | `call_events` (`event_type='risk'`) | `call_events.acknowledged` |

체크리스트는 이 셋을 **합쳐 보여주는 뷰**이고, 체크하면 각자의 원천에 쓴다.
별도 `tasks` 테이블을 만들면 이중 기록이 되고 동기화가 깨진다.

**스키마 변경은 하나뿐:** `call_events`에 `acknowledged_at TEXT` 추가.
지금은 boolean만 있어서 인계에 필요한 시각이 없다.

> **"누가 확인했는지"는 남기지 않는다.** 현재 시스템은 링크 코드 기반이라
> 담당자 개인 식별이 없다. 계정 도입은 범위 밖이므로 **시각까지만** 기록하고,
> 작성자 추적은 로드맵으로 둔다. 없는 것을 있는 척하지 않는다.

---

## 2. 그룹은 시간이 1차, 환자는 토글

둘 다 필요하지만 1차는 하나만 될 수 있다. **시간이 1차다.**
요양사는 `"지금 뭐 해야 하지"`로 움직인다. `"이 환자 뭐 있지"`는 그 방에
들어갔을 때만 필요하다.

상단에 `[시간순 | 환자별]` 토글을 두고 **기본은 시간순**.

---

## 3. 시각을 세 종류로 나눠 배치한다

지금 코드는 전부 한 덩어리로 취급한다. 섞으면 "오늘 중"짜리가 08:00 슬롯에
들어가 시간이 지났다고 놓침 처리된다.

| 종류 | 예 | 배치 |
|---|---|---|
| **즉시성** | 위험 신호 확인 | 시간 무시, **맨 위 고정** |
| **정시성** | 복약 확인 | 해당 시간 슬롯 |
| **당일성** | 관찰 주기 도래 | **"오늘 중"** 그룹. 시간 지나도 놓침 아님 |

## 4. 화면 구조

```
체크사항                                    [시간순 | 환자별]

⚠ 즉시 확인                                          1건
  □ 박순자 · 낙상 신호 상태 확인
    🔵 09:14 "화장실에서 넘어져서 허리가 아프고 일어나기 힘들구나"

08:00 투약                                      ✓ 3/3  ▸ (접힘)

09:00 투약                                      ● 1/2
  ✓ 이정호 · 클로피도그렐            09:02 확인
  □ 박순자 · 리바스티그민 패치
    🔵 08:41 "아침 약을 먹었나? 약을 먹었는지 기억이 안 난다"

오늘 중 · 시각 무관                              ○ 0/2
  □ 박순자 · 레보도파 7일 관찰 주기 도래
    🔵 관련 발화 3건 — 기립 어지럼 2 · 환시 1
  □ 이정호 · 클로피도그렐 7일 관찰 주기 도래

20:00 투약                                      ○ 예정
```

- 상태는 **완료 / 대기 / 놓침**(시간 지난 미완료) 세 가지
- 완료된 그룹은 **접어서** 남은 일만 보이게 한다
- 미완료는 자정에 사라지지 말고 **"어제 미완료"**로 남긴다

---

## 5. ★ 항목에 AI 통화 근거를 붙인다

이 탭이 단순 할 일 목록과 갈리는 지점이다. 요양사가 **방에 들어가기 전에
무엇을 볼지 알고** 간다.

### 5-1. 항목 종류별로 붙이는 근거가 다르다

| 항목 | 붙일 근거 | 시간 창 |
|---|---|---|
| 복약 확인 | 그 시간대 통화의 `medication_uncertain` 발화 | 슬롯 **±2시간** |
| 관찰 주기 도래 | 그 약의 `monitoring_points`에 매핑된 신호 (오늘) | 당일 전체 |
| 위험 확인 | 그 이벤트를 만든 발화 | 해당 이벤트 |

`docs/codex_prompt_medication.md`의 매핑 테이블을 그대로 쓴다.
**새 매핑을 만들지 않는다.**

### 5-2. 규칙

- **관련 신호만 붙인다.** 아무 신호나 붙이면 노이즈가 되어 아무도 안 읽는다
- **근거가 없으면 아무것도 그리지 않는다.** `"관련 발화 없음"` 같은 빈 줄을
  만들지 말 것. 빈 줄이 실제 근거와 같은 공간을 차지한다
- 근거는 **파랑**(출처 표시)으로 그린다. 빨강·호박(상태)과 역할이 겹치지 않게
  분리한다 — `docs/mockups/medication_tab.html`의 `--ai` 토큰과 동일
- 발화가 여러 건이면 **최대 2건 + "외 N건"**

### 5-3. 문구 주의

근거는 **"확인해야 할 이유"**이지 **"이미 확인됨"**이 아니다.

| ❌ | ✅ |
|---|---|
| "복약 혼동이 확인되었습니다" | "통화에서 이런 발화가 있었습니다" |
| "어지럼 증상이 있습니다" | "관련 발화 2건 — 기립 어지럼" |

AI 관찰은 담당자가 직접 확인할 **후보**다. 체크는 여전히 사람이 한다.

## 6. 사이드바 배지

```
체크사항          7/12
```

**퍼센트를 쓰지 않는다.** 항목이 적을 때 `2/3`이 `67%`로 보이면 실제보다
진척된 것처럼 읽힌다. 분수로만 표시한다.

---

## 7. `일정·복약`과의 역할 분담

`일정·복약`은 이제 **체크사항의 형제 탭**이다. 같은 메뉴 안에서 오간다.

| 탭 | 역할 |
|---|---|
| **체크리스트** | **무엇을 할지** — 모든 할 일의 단일 목록 |
| **일정·복약** | **어떻게 할지** — 관찰 체크리스트 실행, 증상 역조회, 약 정보, 달력 |

- 체크리스트에서 `박순자 · 레보도파 관찰 주기 도래`를 누르면
  **일정·복약의 실행 화면으로 이동**하고, 저장하면 체크리스트로 돌아온다
- 일정·복약에서는 **"오늘 확인할 관찰" 목록을 만들지 않는다.** 그 목록은
  체크리스트가 유일하게 갖는다. 두 곳에 그리면 안 된다

`docs/mockups/medication_tab.html`의 **첫 번째 화면은 체크리스트의 디자인
참고**로 읽는다. 두 번째·세 번째 화면(관찰 체크리스트 실행, 증상 역조회)이
일정·복약이다.

## 8. `인계` 화면 (구 특이사항 자리)

### 8-1. 무엇을 그리나

인계는 **새로 쓰는 문서가 아니라 체크의 결과**다. 대부분 자동 집계이고,
담당자가 쓰는 것은 메모 한 칸뿐이다.

```
인계                                    주간 근무 · 08/12

┌ 이전 근무에서 받은 것 · 야간 (08/12 06:50 마감) ──────┐
│  · 박순자 레보도파 관찰 주기 미완료 — 주간에 확인 필요  │
│  · 03시경 환시 표현 2회 — 조명 확인함                 │
│  메모: "새벽에 깨서 불안해하심. 딸 통화 후 안정."       │
└──────────────────────────────────────────────────┘

오늘 확인한 것                                   9/12
  박순자   ✓ 낙상 신호 확인            09:20
           ✗ 레보도파 관찰 주기        미완료
  이정호   ✓ 클로피도그렐              09:02

의료진에게 보고한 것                              1건
  박순자 · 환시·혼란 변화 (레보도파 보고 기준 해당)  15:50

다음 근무자가 볼 것              ← 자동 생성
  · 박순자 레보도파 관찰 주기 미완료
  · 15시 이후 환시 표현 반복 — 조명 확인 권장

메모  [                                        ]

근무조  [ 주간 ▾ ]                      [ 인계 마감 ]
```

### 8-2. "다음 근무자가 볼 것"은 자동 생성한다

담당자가 빈 칸을 채우게 하지 않는다. 아래 세 가지를 모아 문장으로 만든다.

| 재료 | 원천 |
|---|---|
| 미완료 체크 항목 | 체크리스트의 세 테이블 |
| 오늘 평소 범위를 벗어난 지표 | Phase 4 관리도 (없으면 이 줄은 생략) |
| 의료진 보고 대기 | 약–관찰 escalation 해당 건 |

**Phase 4가 아직 없으면 두 번째 줄은 만들지 않는다.** 없는 값을 지어내지 말 것.

### 8-3. 신규 테이블 — 이번 작업의 유일한 새 테이블

```sql
CREATE TABLE IF NOT EXISTS handovers (
    handover_id INTEGER PRIMARY KEY AUTOINCREMENT,
    shift       TEXT NOT NULL,   -- 'day' | 'evening' | 'night'
    closed_at   TEXT NOT NULL,
    note        TEXT,
    created_at  TEXT DEFAULT CURRENT_TIMESTAMP
);
```

나머지 내용(확인한 것·보고한 것)은 **저장하지 않는다.** `closed_at` 기준으로
기존 테이블을 조회해 그릴 수 있다. 복사해 두면 원천과 어긋난다.

### 8-4. 인계는 어르신 단위가 아니라 근무 단위다

담당자는 맡은 **전원**을 한 번에 인계한다. 어르신마다 인계장을 쓰지 않는다.

- 인계 화면은 **어르신 선택과 무관하게** 담당 어르신 전원을 섹션으로 나눠
  한 장에 보여준다
- `handovers`에 `elder_id`를 넣지 않는다 (위 스키마에 없는 이유)

### 8-5. 작성자 — 근무조까지만 남긴다

현재 시스템은 링크 코드 기반이라 **담당자 개인 식별이 없다.** 계정 도입은
범위 밖이므로 `shift`(주간/저녁/야간) 드롭다운까지만 둔다.

- 화면에는 `"주간 근무 · 06:50 마감"`으로 표시한다
- **개인 이름을 표시하거나 추측하지 않는다.** 없는 것을 있는 척하지 않는다

### 8-6. 체크사항과 잇는 배너

체크리스트 맨 위에 **한 줄짜리** 배너를 둔다. 그 이상 넣으면 체크리스트가
무거워진다.

```
📋 야간 근무 인계 2건            보기 ›
```

누르면 인계 화면으로 간다.

## 제약

- `docs/analysis_design.md` 15장 문구 규칙을 지킨다
- **새 신호 어휘를 만들지 않는다.** 스키마 변경은 딱 두 가지 —
  `call_events.acknowledged_at` 추가, `handovers` 테이블 신설
- 인계 내용을 `handovers`에 복사 저장하지 않는다 (8-3)
- 기존 테스트를 통과시킨다 (현재 190개)
- 접근성: 체크박스 터치 영역 최소 44px, 키보드 포커스 표시,
  `DisplaySettings`의 글자 크기 설정이 계속 동작해야 한다
