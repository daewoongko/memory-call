# 결정 기록

이 문서는 "무엇을 정해야 하는가" 목록이 아니라 **이미 정한 것과 그 근거** 다.
되돌리자는 제안이 반복되는 것을 막기 위해 남긴다.

각 항목의 근거는 셋 중 하나다.

- **제약** — 2주·1인·무료 티어라는 조건에서 나온 결정
- **실측** — 직접 해보고 안 된 것
- **정책** — 안전 정책이 요구하는 것

---

## 1. 기술 스택

### 1.1 SQLite (PostgreSQL / pgvector 아님)

**제약.** 기억이 30개 규모다. 벡터DB가 필요한 양이 아니고, 1인 개발에서
Postgres 운영은 순수 비용이다. `backend/schema.sql` 12테이블로 충분하다.

### 1.2 브라우저 `MediaRecorder` + REST (WebRTC / LiveKit 아님)

**제약.** 반이중(누르고 말하기)으로 충분하다. LiveKit은 시그널링 서버·TURN·토큰
발급이 딸려 오고, 그걸 붙이는 시간이 안전 레이어를 만드는 시간을 잡아먹는다.

> 이전 버전(`memory-link-call`)에서 LiveKit 기반으로 시작했다가 되돌렸다.
> `infra/livekit.yaml` 과 `livekit_tokens.py` 는 이관하지 않았다.

### 1.3 React 19 + Vite (Next.js 아님)

**제약.** SSR·라우팅·API 라우트가 필요 없다. 화면 하나에 상태머신 하나다.
`#guardian` 해시로 보호자 화면을 가른다.

### 1.4 단일 레포 평면 구조 (pnpm 모노레포 아님)

**제약.** `backend/` + `frontend/` + `tools/` 로 끝난다. 워크스페이스 배선과
공유 패키지 빌드 순서를 관리할 사람이 없다.

> 이전 버전은 `apps/` + `packages/` + `services/` 3층 모노레포였다. 화면 코드가
> `app/page.tsx` 한 파일에 1,000줄 넘게 쌓여 있었고, 정작 `services/media-worker`
> 는 비어 있었다. 구조가 깊어진 만큼 실제 구현이 얇아졌다.

### 1.5 사진 2장 볼륨 전환 (SadTalker / D-ID 실시간 립싱크 아님)

**실측.** 응답당 수십 초가 걸려 대화가 성립하지 않는다. 입 다문 사진과 벌린
사진을 오디오 볼륨으로 전환하는 방식으로 대체했다.

### 1.6 모핑 인트로는 오프라인 사전 생성

**실측.** 통화 중 생성하면 건당 수백 원에 1~3분이 걸린다. 페르소나 등록 시
mp4 1개를 만들어 두고 통화 때는 재생만 한다.

### 1.7 localhost 데모 (Docker / 클라우드 배포 아님)

**제약.** 발표 데모다. 다만 `Dockerfile` 과 `render.yaml` 은 남겨 둔다 —
공개 프리뷰용으로 한 번 배포했고, 되돌릴 이유가 없다.

## 2. 아키텍처

### 2.1 LLM 응답은 JSON

**정책.** `reply` 만 받으면 안전 검사를 텍스트 매칭으로만 해야 한다. 모델이
`used_memory_ids` / `certainty` / `risk` / `medication_status` 를 스스로
신고하게 하면 검사가 정확해지고, 통화 리포트와 설명 가능성 데이터가 공짜로 나온다.

단 **신고값은 검증 대상이다.** `docs/02-safety-policy.md` 6절.

### 2.2 모든 LLM 호출은 `backend/llm.py` 를 거친다

**제약.** 다른 파일에서 직접 `OpenAI()` 를 만들지 않는다. 모델 교체가 `.env`
세 줄로 끝나야 한다. 429 백오프와 JSON 파싱 방어도 여기 한 곳에 모은다.

### 2.3 `prohibited` 기억도 프롬프트에 넣는다

**실측.** 직관과 반대다. 빼면 모델이 근거 없이 지어낸다. 돌아가신 할머니를 모른
채 "곧 오실 거야" 같은 거짓 위안을 만든다. 넣고 취급 방법을 명시해야 정책대로
대응한다.

### 2.4 숫자는 규칙이 만들고 문장만 LLM이 만든다

**정책.** 리포트의 반복 질문 횟수, 복약 상태, 위험 건수는 전부 DB 집계다.
LLM에는 확정된 집계 결과만 넘긴다. 모델이 실패해도 리포트는 나온다.

### 2.5 복약 안내 문장은 LLM을 거치지 않는다

**정책.** 약 이름과 복용량을 모델이 지어내면 그대로 위험이 된다. 등록된 값을
규칙으로 조립한다. 어떤 약인지도 모델이 아니라 서버가 고른다.

### 2.6 AI는 스스로 기억을 늘리지 못한다

**정책.** 통화 중 처음 나온 이야기는 `unverified_recall` 로 남고, 보호자가
승인해야만 기억이 된다. `recall_reviews` 에 결정을 남겨 같은 것을 다시 묻지 않는다.

### 2.7 AI 고지는 상태로 강제한다

**정책.** 절대 규칙 7번은 "정체성을 직접 물으면 거짓말 금지"다. 이걸 프롬프트에만
맡기지 않고 `calls.status = 'ai_disclosure'` 단계를 통화 상태 머신에 넣어,
고지를 지나지 않으면 대화 턴으로 갈 수 없게 한다.

> 이 아이디어는 이전 버전의 `CallStatus.AI_DISCLOSURE` 에서 가져왔다.

## 3. 두 레포 통합 (2026-07-30)

`memory-link-call` 과 `memory-call` 두 레포를 왔다갔다 하며 작업한 결과 코드가
갈라졌다. `memory-call` 을 기준으로 합쳤다.

### 기준을 `memory-call` 로 잡은 이유

| 항목 | `memory-link-call` | `memory-call` |
|---|---|---|
| `safety.py` | 47줄, 복약 규칙 하나만 | 341줄, 절대 규칙 8개 전부 |
| 안전 자동 평가 | 없음 | `eval.py` + 시나리오 22개 |
| 화면 분해 | `page.tsx` 한 파일에 1,000줄+ | `screens/` 15 + `components/` 7 |
| 모핑 파이프라인 | 없음 | `make_morph` / `make_loops` / `fix_loop` |
| 발표 대본 | 없음 | `demo_script.md` |
| 배포 | 안 됨 | `render.yaml` 로 배포됨 |

`memory-link-call` 의 `docs/02-safety-policy.md` 는 원칙 8개와 상태 전이를 잘
적어 놨지만 **코드는 그중 복약 하나만 구현했다.** `certainty`, `exclusiv` 같은
심볼은 레포 전체에 없었다. 문서가 앞서고 구현이 비어 있었다.

### `memory-link-call` 에서 가져온 것

- `docs/00~06` 설계 문서 (이 파일 포함) — 실제 구조에 맞게 재작성
- `CallStatus.AI_DISCLOSURE` → `calls.status = 'ai_disclosure'`
- `MedicationEventStatus.GUARDIAN_CONFIRMED` → `medication_logs.status`
- API 계약 테스트 개념 → `tests/`

### 가져오지 않은 것

LiveKit, Docker Compose, pnpm 모노레포, Next.js, `packages/contracts` (TS),
Postgres. 위 1절의 결정과 충돌한다.
