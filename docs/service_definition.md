# 서비스 정의

발표와 구현이 같은 문장을 쓰기 위한 문서다. 기능 명세가 아니라 **왜 이 기능이
있는지**를 고정한다. 기능 목록은 `CLAUDE.md`, 실행 방법은 `README.md`를 본다.

## 한 문장

> 치매 환자가 일상 속에서 잃어가는 기억과 현재의 맥락을 가족 기반 AI 영상통화로
> 자연스럽게 연결하고, 보호자의 반복적인 설명과 정서적 돌봄 부담을 줄인다.

---

## 문제 정의

**환자.** 치매는 기억력만 잃는 병이 아니다. 지남력·판단력·실행능력·언어능력이
함께 떨어지면서 지금이 언제인지, 여기가 어디인지, 방금 무슨 일이 있었는지에 대한
맥락이 끊어진다. 그 끊김이 불안·초조·반복행동으로 나타난다.

**보호자.** 그래서 가족은 같은 설명을 하루에 몇 번씩 되풀이하고, 그때마다
안심시켜야 한다. 반복전화는 이 부담이 겉으로 드러난 형태일 뿐 원인이 아니다.

이 순서가 중요하다. 예전 정의는 "반복전화 때문에 보호자가 힘들다"에서 시작했는데,
그러면 서비스가 전화를 대신 받아주는 도구에서 멈춘다. **환자의 맥락 상실을 먼저
놓고 보호자 부담을 그 결과로 설명해야** 통화 한 통이 왜 의미가 있는지가 나온다.

## 목적

가족과의 AI 영상통화를 통해 끊어진 일상 맥락을 반복적으로 연결하고, 보호자의
지속적인 설명·안심 부담을 줄인다.

### 목적이 아닌 것

- 치매 **치료**
- 치매 **예방**
- 기억력 **회복**
- 진단·의학적 판단

이 네 가지는 발표에서도 말하지 않는다. 근거가 없고, 하나라도 입에 담는 순간
나머지 주장 전체의 신뢰가 같이 떨어진다. 우리가 말하는 것은 **현재 상황 이해
지원 / 정서적 안정 / 생활 행동 지원 / 보호자 부담 감소** 네 가지뿐이다.

---

## AI가 개입하는 4개 축

이 넷 밖으로 나가지 않는다. 치매의 모든 증상을 다루려 하면 아무것도 못 만든다.

| 축 | 환자 발화 예 | AI가 하는 일 |
|---|---|---|
| **A. 기억·지남력** | "오늘이 며칠이지?" "대웅이는 몇 살이지?" | 등록된 시간·장소·사람·일정을 대화 속에서 제공 |
| **B. 정서** | "대웅이가 안 와." "무서워." | 익숙한 얼굴·목소리·확인된 추억으로 안정 |
| **C. 일상 행동** | 복약, 식사, 수분 | 한 번에 하나씩 안내. 지시가 아니라 확인 |
| **D. 변화 감지** | — | AI가 해결하지 않고 보호자에게 넘긴다 |

D축의 원칙이 특히 중요하다. **AI는 변화를 판단하지 않고 관찰만 보고한다.**
"우울증이 의심됩니다"는 하지 않는다. "최근 7일 저녁 시간대에 불안 표현이
늘었습니다"까지만 한다.

## 3단계 구조

발표에서 서비스를 설명할 때 쓰는 뼈대다.

**① Connect — 기억을 연결한다**
가족 얼굴, 목소리, 추억 사진, 과거 이야기 → 익숙함을 만든다.

**② Orient — 현재를 연결한다**
시간, 장소, 사람, 일정, 식사, 약 → 지금의 맥락을 준다.

**③ Care — 일상을 연결한다**
대화, 행동 유도, 불안 완화, 생활 확인, 변화 기록 → 보호자에게 전달한다.

## 기존 기능은 그대로 두고 이유만 바꾼다

없앨 기능은 없다. 달라지는 것은 각 기능을 설명하는 이유다.

| 기능 | 예전 의미 | 지금의 의미 | 단계 |
|---|---|---|---|
| AI 영상통화 | 보호자 대신 통화 | 인지·정서 케어 인터페이스 | — |
| 가족 목소리 클론 | 가족처럼 대화 | 정서적 안정 단서 | Connect |
| 얼굴 모핑 | 과거→현재 얼굴 | 시간·기억 연결 단서 | Connect |
| 추억 기억 DB | 대화 콘텐츠 | 장기기억을 이용한 인지 앵커 | Connect |
| 일정·시각 블록 | 약속 확인용 | 시간 지남력 제공 | Orient |
| 반복질문 대응 | 보호자 부담 감소 | 불안·망각 대응 | Care |
| 복약 알림 | 생활 편의 | 실행능력 보조 | Care |
| 보호자 리포트 | 통화 요약 | 인지·행동 변화 관찰 | Care |

## 이 확장이 안전 정책에 거는 부하

**여기가 제일 중요하다.**

지금까지 이 서비스는 "모르는 것은 단언하지 않는다"로 안전을 지켰다. 그런데
"현재 맥락을 제공한다"는 것은 **AI에게 새로운 단언 권한을 주는 방향**이다.
두 방향이 정면으로 부딪힌다.

해소하는 문장은 하나다.

> **맥락은 등록된 사실에서만 나온다. 등록되지 않은 것은 맥락으로도 말하지 않는다.**

날짜와 요일은 서버가 계산하니 단언해도 된다. 등록된 일정도 마찬가지다. 그러나
환자가 지금 어디에 있는지는 시스템이 모른다. "할아버지는 지금 집에 계세요"는
그럴듯하지만 **근거 없는 단언이고 절대 규칙 2번 위반**이다.

맥락 제공 기능을 넣을 때는 기능보다 먼저 그것을 어긴 경우를 잡는 eval 시나리오를
넣는다. 순서가 뒤집히면 통과율이 떨어진 채로 발표에 들어간다.

## 범위 밖

로드맵으로만 말하고 만들지 않는다.

- 지도 API, 외출 안내, 공간 지남력의 위치 기반 기능
- 운동·활동 유도
- 수면·식욕·성격 변화의 자동 판정
- 환시·오인·망상에 대한 개입
- 우울·불안의 진단적 평가

이 목록은 `CLAUDE.md`의 "명시적으로 하지 않기로 한 것"과 같은 무게로 취급한다.

## 구현 상태

문서가 코드보다 앞서 나가면 다음 단계에서 혼선이 생긴다. 현재 사실은 이렇다.

| 항목 | 상태 | 근거 |
|---|---|---|
| 시간 지남력의 사실 원천 | **있음** | `persona.py`가 현재 시각·요일과 일정을 규칙으로 조립해 프롬프트에 넣는다 |
| 맥락 제공을 강제하는 장치 | **있음** | `safety.py`의 `ContextRule`이 "이런 발화에는 이런 요소가 반드시 들어가야 한다"를 검사한다 |
| 7일 변화 비교 | **있음** | `report.py`의 `period()` / `_delta()` |
| 반복질문·복약·위험 집계 | **있음** | `report.py` |
| **장소 지남력의 사실 원천** | **없음** | `elder_profiles`에 거주 형태·동거인 컬럼이 없다. 지금 시키면 모델이 지어낸다 |
| 지남력 혼동의 분류 | **없음** | LLM JSON의 `intent`에 해당 축이 없다 |
| 저강도 정서(불안·초조)의 구조화 | **없음** | `risk`는 있으나 그 아래 단계가 없다 |
| 리포트의 4축 재구성 | **없음** | 집계는 다 있고 묶는 방식만 없다 |

없는 항목은 순서대로 채운다. 채우기 전에 발표에서 있다고 말하지 않는다.
