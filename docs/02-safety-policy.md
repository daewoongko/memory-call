# 안전 정책

이 프로젝트의 차별점은 아바타 기술이 아니라 안전 정책이다. 얼굴 모핑이나 음성
클론이 실패해도 이 계층은 살아남는다.

이 문서는 **정책이 코드의 어디에 구현되어 있는지**까지 명시한다. 정책만 적어
두고 구현이 비어 있으면 문서가 아니라 희망이다.

## 1. 방어 계층

정책은 세 겹으로 강제한다. 위쪽은 부탁이고 아래쪽이 강제다.

| 계층 | 위치 | 성격 | 모델을 바꾸면 |
|---|---|---|---|
| 1차 | `backend/prompts/persona_system.md` | 프롬프트 (부탁) | 동작이 바뀐다 |
| 2차 | `backend/safety.py` | 규칙 검사 (강제) | **바뀌지 않는다** |
| 3차 | `tools/eval.py` + `scenarios.json` | 자동 평가 (회귀 감지) | 통과율로 드러난다 |

2차가 핵심이다. LLM 응답을 그대로 내보내지 않고 규칙으로 한 번 거른다.

현재 통과율: **프롬프트만 82% / safety 포함 91%** (시나리오 22개 기준).
`persona_system.md` 나 `safety.py` 를 고칠 때마다 `python tools/eval.py --sleep 5`
를 돌린다.

## 2. 기본 원칙

1. AI는 가족·의료진·응급 대응자를 대체한다고 표현하지 않는다.
2. AI 통화임을 통화 시작 전에 알리고, 질문을 받으면 항상 사실대로 답한다.
3. 확인되지 않은 기억의 사실 여부를 확정하지 않는다.
4. 감정은 인정하되 망상·오인·존재하지 않는 약속을 강화하지 않는다.
5. 약의 용량·종류·복용 횟수를 생성하거나 변경하지 않는다.
6. 진단형 표현을 쓰지 않고 관찰된 발화와 변화만 전달한다.
7. 비밀 유지·배타적 관계·AI 의존을 유도하지 않는다.
8. 사용자가 종료를 원하면 안전 확인 후 통화를 종료한다.

## 3. 절대 규칙과 구현 대응

`CLAUDE.md` 의 8개 절대 규칙이 `safety.py` 의 어느 코드로 강제되는지다.
**빈 칸이 있으면 그 규칙은 프롬프트에만 의존한다는 뜻이므로 채워야 한다.**

| # | 절대 규칙 | `safety.py` 코드 | 처리 |
|---|---|---|---|
| 1 | 등록된 일정에 없는 방문·통화 약속 생성 금지 | `PROMISE_WITHOUT_SCHEDULE` | BLOCK |
| 2 | `verified` 기억만 사실로 사용 | `GHOST_MEMORY_ID`, `GHOST_SCHEDULE_ID`, `UNGROUNDED_CERTAINTY` | 보정 |
| 2 | `partial` 은 불확실성 표현 필수 | `PARTIAL_WITHOUT_HEDGE` | PREFIX |
| 3 | 처음 듣는 기억은 사실 확정 금지 | `RECALL_CERTAINTY_FIXED` | 보정 |
| 4 | `prohibited` 기억을 먼저 꺼내지 않되 거짓말도 금지 | `PROHIBITED_TOPIC_LEAK` | BLOCK |
| 4 | (같음) 인용 자체는 기록 | `PROHIBITED_MEMORY_CITED` | FLAG |
| 4 | (같음) 고인 언급에 감정 인정 필수 | `DECEASED_UNHANDLED` | APPEND |
| 5 | 복약 용량 변경·추가·중단 권고 금지 | `MEDICATION_INSTRUCTION` | BLOCK |
| 6 | 정서적 독점 유도 금지 | `EMOTIONAL_EXCLUSIVITY`, `CLINGY_CLOSING` | BLOCK |
| 6 | (같음) 의존 표현은 가족으로 연결 | `EXCLUSIVITY_UNREDIRECTED` | APPEND |
| 7 | 정체성을 직접 물으면 명시적 거짓말 금지 | `IDENTITY_UNEXPLAINED` | APPEND |
| 8 | 금융·법률 요청 수행 금지 | `FINANCIAL` | BLOCK |

규칙 번호에 대응하지 않는 보조 규칙:

| 코드 | 목적 | 처리 |
|---|---|---|
| `FORMAL_SPEECH_DRIFT` | 반말 페르소나인데 존댓말로 이탈 | FLAG |
| `LONELINESS_UNACKNOWLEDGED` | 외로움 호소에 사실만 답함 | APPEND |
| `CLOSING_NOT_HONORED` | 종료 신호에 마무리 인사 없음 | APPEND |

## 4. 처리 방식 네 가지

`safety.py` 의 각 규칙은 넷 중 하나로 처리한다.

| 처리 | 의미 | 결과 |
|---|---|---|
| `BLOCK` | 응답 전체를 사전 승인된 안전 문장으로 교체 | `certainty="none"`, 인용 전부 제거 |
| `PREFIX` | 응답 앞에 불확실성 표현을 덧붙임 | `HEDGE_PREFIX` 삽입 |
| `APPEND` | 응답 뒤에 빠진 필수 요소를 덧붙임 | `ContextRule.append` |
| `FLAG` | 기록만 남기고 응답은 통과 | `safety_flags` 에 적재 |

**안전 검사가 실패하면 원문을 부분 수정해 쓰지 않는다.** 사전 승인된 안전
문장으로 통째로 바꾸거나 재질문한다. 부분 수정은 무엇이 남았는지 보증할 수 없다.

## 5. 응답 처리 순서

```text
브라우저 음성 인식 결과
→ 기억·일정·복약 조회 (backend/memories.py, medication.py)
→ 시스템 프롬프트 조립 (backend/persona.py)
→ LLM 구조화 응답 (backend/llm.py)          ← JSON 강제
→ 근거 검증: 인용한 기억·일정이 실재하는가   ← safety.py 1~2단계
→ 문장 패턴 규칙 (RULES)                    ← safety.py 3단계
→ 필수 요소 규칙 (CONTEXT_RULES)            ← safety.py 3.5단계
→ partial 기억 불확실성 표현                ← safety.py 4단계
→ prohibited 인용 기록                      ← safety.py 5단계
→ 브라우저 음성 합성
```

### 검사가 두 방향인 이유

문제 발언을 **하지 않는 것만으로는 부족하다.** 할아버지가 "너밖에 없다"고
말했을 때 AI가 금지 표현을 쓰지 않았더라도, 다른 가족으로 연결하지 않으면
정서적 독점을 방치한 것이다.

- `RULES` — AI가 **하면 안 되는 말**을 잡는다 (응답 검사)
- `CONTEXT_RULES` — 할아버지 발화가 특정 패턴일 때 AI 응답에 **반드시
  들어가야 하는 요소**를 잡는다 (발화 ↔ 응답 대응 검사)

## 6. 모델 신고값을 신뢰하지 않는다

LLM은 `reply` 외에 `used_memory_ids` / `certainty` / `risk` /
`medication_status` / `unverified_recall` 을 스스로 신고한다. 신고를 받으면
검사가 정확해지고 리포트 데이터가 공짜로 나온다.

**그러나 신고값은 검증 대상이다.**

- `used_memory_ids` 가 실재하는 기억인지 대조한다 → `GHOST_MEMORY_ID`
- `certainty="verified"` 인데 인용이 없으면 강등한다 → `UNGROUNDED_CERTAINTY`
- `unverified_recall` 이 있는데 `certainty` 가 다르면 덮어쓴다 →
  `RECALL_CERTAINTY_FIXED`
- `eval.py` 의 `reply_must_not_match` 는 신고값이 아니라 **실제 문장을
  정규식으로** 검사한다

`RECALL_CERTAINTY_FIXED` 는 특히 중요하다. 이 값이 틀리면 미확인 회상이 보호자
확인 대기함에 올라가지 않아 승인 절차가 통째로 무너진다.

## 7. 기억 정책

상태값은 `memories.status` 의 CHECK 제약과 일치한다 (소문자).

| 상태 | 사실 표현 | 프롬프트 투입 | 보호자 확인 |
|---|---|---|---|
| `verified` | 허용 | 허용 | 불필요 |
| `partial` | 불확실성 명시 필수 | 허용 | 권장 |
| `unverified` | **사실 확정 금지**, 회상 유도만 | 사실 컨텍스트에서 제외 | 필수 |
| `prohibited` | 금지 | **투입함** (아래 참고) | 상태 변경 전까지 불필요 |

필수 규칙:

- 응답에서 가족 관련 사실을 사용했다면 `used_memory_ids` 가 있어야 한다.
- 날짜·장소·인물·약속은 근거 필드에 없는 내용을 보충하지 않는다.
- 미확인 회상에는 감정 인정과 개방형 질문만 사용한다.
- **AI는 스스로 기억을 늘리지 못한다.** 통화 중 처음 나온 이야기는
  `unverified_recall` 로 남고 보호자가 승인해야만 기억이 된다
  (`recall_reviews` 테이블).

### `prohibited` 기억을 프롬프트에 넣는 이유

직관과 반대다. **빼면 모델이 근거 없이 지어낸다.** 돌아가신 할머니를 모른 채
"곧 오실 거야" 같은 거짓 위안을 만든다. 넣고 취급 방법을 명시해야 정책대로
대응한다.

단, 금지 **사유** 는 보호자 검토 화면에서만 접근 가능하고 AI에는 전달하지 않는다.

## 8. 복약 정책

**복약 안내 문장은 LLM을 거치지 않는다.** 약 이름과 복용량을 모델이 지어내면
그대로 위험이 되므로 등록된 값을 규칙으로 조립한다 (`backend/medication.py`).
어떤 약인지도 모델이 아니라 서버가 고른다.

LLM이 만들거나 수정할 수 없는 값:

- 약 이름 · 용량 · 복용 시간 · 복용 횟수 · 식전/식후 · 중복 복용 판단 결과

### 허용 상태 전이

`medication_logs.status` 의 CHECK 제약과 일치한다.

```text
(등록: medications 테이블)
→ 통화 중 선제 안내
→ USER_CONFIRMED | UNCLEAR | REFUSED | DUPLICATE_SUSPECTED
→ GUARDIAN_CONFIRMED
```

`GUARDIAN_CONFIRMED` 는 보호자가 별도로 확인한 상태다. 본인 응답과 구분해야
리포트에서 `본인 응답` / `보호자 확인` 을 분리할 수 있다.

카메라나 기기 확인이 추가되면 별도 증거 상태로 기록하며 "복용 완료"와 자동으로
동일시하지 않는다.

안전 문장 원칙:

- 등록 정보만 읽어 준다.
- 추가 복용이나 보충 복용을 지시하지 않는다.
- 이미 먹었는지 혼동하면 다시 먹으라고 하지 않는다.
- 중복 가능성이 있으면 추가 복용을 멈추고 보호자 확인을 요청한다.

⚠️ **부정문 함정** — `"약을 더 드시지 말고"` 라는 안전 문장 자체가 복약 지시
규칙에 걸린 적이 있다. `MEDICATION_INSTRUCTION` 패턴은 모두
`(?!지\s*(말|마|않))` 부정 전방탐색을 붙여 이를 막는다. 패턴을 추가할 때
반드시 같이 붙인다.

## 9. 위험 정책

| 단계 | 의미 | 시스템 행동 |
|---|---|---|
| NORMAL | 일반 대화 | 대화 유지 |
| ATTENTION | 리포트 확인 필요 | `call_events` 기록, 리포트 강조 |
| HIGH | 빠른 보호자 확인 필요 | 짧은 확인 질문, 즉시 알림, 통화 유지 |
| EMERGENCY | 즉각적인 사람의 개입 가능성 | 승인된 최소 질문, 보호자 순차 알림 |

실제 긴급기관 연결과 구체적인 의료 안내는 승인된 운영 정책 없이 실행하지
않는다. 실사용 파일럿 전에 전문가 검토가 필요하다.

요구사항:

- 탐지 원문·시간·최종 정책 결과를 기록한다 (`call_events`, `event_type='risk'`).
- 사용자를 심문하지 않고 한 번에 하나의 짧은 질문만 한다.
- 같은 위험 사건의 알림 중복을 제어한다 (`acknowledged` 플래그).
- 보호자 수신·열람·확인·조치 상태를 구분한다.
- 위험 상황에서 얼굴 효과보다 음성 통화 유지와 지연 최소화를 우선한다.

### 보호자 통보는 약속이 아니다

`"아빠한테 연락할게"` 를 거짓 약속으로 차단하면 위험 상황에서 반드시 해야 할
행동을 막는다. `PROMISE_WITHOUT_SCHEDULE` 은 **문장 단위로** 검사하고
`exempt_words = ["아빠", "엄마", "가족", "보호자", "119", "구급", "병원"]`
면제 목록을 둔다.

## 10. 금지 표현

- "다른 가족은 필요 없어."
- "나한테만 전화해."
- "이건 우리 둘만의 비밀이야."
- "전화를 끊으면 내가 외로워."
- "가족보다 내가 더 잘 알아."
- 확인되지 않은 방문·선물·약속을 확정하는 표현
- 질병 악화나 정신 상태를 진단하는 표현
- 등록되지 않은 약 복용 또는 용량 변경 지시

금지 표현은 단순 문자열 필터 외에 `scenarios.json` 의 의미 기반 테스트 세트로
검증한다.

⚠️ **부분 문자열 함정** — `"아버지"` 는 `"할아버지"` 안에 들어 있다. 이것 때문에
정서 독점 규칙이 통째로 무력화된 적이 있다. `ContextRule.require_any` 에
`"아버지"` 처럼 다른 호칭의 부분 문자열이 되는 말을 넣지 말 것.

## 11. 리포트 정책

**숫자는 규칙이 만들고 문장만 LLM이 만든다.** 반복 질문 횟수, 복약 상태, 위험
건수는 전부 DB 집계다. LLM에는 확정된 집계 결과만 넘기고 읽기 좋은 문장으로
바꾸게 한다. 모델이 실패해도 리포트는 나온다.

- 진단 대신 관찰 사실과 이전 기준선 대비 변화를 표시한다.
- 보호자 확인이 필요한 미확인 기억을 별도 구역에 둔다 (`new_recalls`).
- 위험 신호는 요약보다 먼저 표시한다.
- AI 추론과 사용자의 직접 발화를 구분한다.
- 복약은 `본인 응답` / `추가 증거` / `보호자 확인` 을 분리한다.
- 낮은 신뢰도의 음성 인식 결과는 확정 사실로 쓰지 않는다.

## 12. 모델 실패 및 폴백

- 음성 인식 신뢰도가 낮으면 짧게 다시 묻는다.
- 기억 검색이 실패하면 가족 사실을 쓰지 않는 일반 대화로 전환한다.
- LLM 또는 안전 검사 실패 시 승인된 안내 문장으로 전환한다
  (`backend/llm.py` 가 429 백오프와 JSON 파싱 방어를 담당).
- 개인화 TTS 실패 시 브라우저 기본 TTS로 전환한다.
- 영상 생성 실패 시 정지 이미지 전환으로 폴백한다.
- 핵심 안전 서비스가 실패하면 AI 통화를 시작하지 않거나 안전하게 종료한다.

## 13. 출시 차단 조건

다음 중 하나라도 발생하면 다음 단계로 넘어가지 않는다.

- 미확인 기억을 사실로 말함
- 등록되지 않은 약 정보 또는 용량을 생성함
