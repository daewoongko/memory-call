# 슬라이드 구성 — 10분 발표 (19장)

`docs/presentation_10min.md` 대본에 1:1로 대응한다. 대본을 고치면 이 문서도
같이 고친다. 슬라이드 번호는 대본의 `[S번호]`와 같다.

---

## 전체 원칙

**한 장에 한 메시지.** 19장에 10분이면 장당 평균 31초다. 텍스트가 많으면
청중이 읽느라 발표자를 안 본다. 감동 발표에서 그건 치명적이다.

**말할 문장을 슬라이드에 쓰지 않는다.** 슬라이드에 있는 걸 그대로 읽으면
발표자가 필요 없어진다. 슬라이드는 **키워드**, 발표자가 **문장**.

**감정 구간은 검은 화면.** S2, S3, S9, S18, S19는 배경을 어둡게 하고 글자
하나만 둔다. 정보 구간(S12, S14, S15, S16)만 밝게 간다. 이 명암 대비 자체가
발표의 리듬이 된다.

**폰트 크기 하한 28pt.** 발표장 뒤에서 안 보이면 없는 것과 같다.
본문은 32pt 이상, 강조는 60pt 이상.

경고는 노랑(`#D9A441`)까지만 간다. 실제 앱의 위험 띠도 노란색이다.

## 2부 — 문제 정의 (S4–S6)

### S4 · 실제 경험 [00:55–01:25]

```
┌──────────────────────────────────────┐
│                                      │
│   [사진 또는 짧은 문장 한 줄]          │
│                                      │
└──────────────────────────────────────┘
```

**⚠️ 발표자가 직접 채우는 슬라이드.** 세 가지 중 하나를 고른다.

| 선택 | 조건 | 효과 |
|---|---|---|
| A. 사진 한 장 | 동의를 받은 실제 사진. 얼굴이 안 보여도 좋다(현관, 달력, 손) | 가장 강함 |
| B. 문장 한 줄 | 사진이 없거나 동의가 애매할 때 | 안전하고 충분히 강함 |
| C. 슬라이드 없음 | 실제 경험이 없을 때 | **지어내는 것보다 훨씬 낫다** |

**하지 말 것**
- 스톡 이미지의 슬픈 노인 사진 → 감정을 산 것처럼 보인다
- 통계 숫자("치매 환자 100만 명") → 이 자리에서는 감정을 죽인다.
  숫자를 꼭 넣고 싶으면 S5 하단에 작게 한 줄
- 얼굴 식별이 가능한 타인 사진을 동의 없이 사용

**B를 고를 때 쓸 형식** — 발표자가 실제로 겪은 한 장면. 예:

```
       오늘이 무슨 요일인지를
       잊으셨습니다.
```

### S5 · 치매는 기억력만 잃는 병이 아니다 [01:25–01:50]

```
┌──────────────────────────────────────┐
│  치매는 기억력만 잃는 병이 아닙니다     │
│                                      │
│   기억력   지남력   판단력   실행능력   │
│     ▼       ▼       ▼       ▼        │
│  ┌────────────────────────────────┐  │
│  │      맥 락 이   끊 어 진 다      │  │
│  └────────────────────────────────┘  │
│              ▼                       │
│      불안 · 초조 · 반복 행동           │
└──────────────────────────────────────┘
```

- 배경: 밝음(정보 구간으로 전환)
- "기억력"만 회색, 나머지 셋은 강조색 → **빠진 세 개**가 보이게
- 세로 흐름이 원인→결과로 읽혀야 한다

### S6 · 반복전화는 증상이다 [01:50–02:20]

```
┌──────────────────────────────────────┐
│                                      │
│   ✕  반복전화 → 보호자 부담            │
│      = 전화를 대신 받아주는 앱          │
│                                      │
│   ────────────────────────────       │
│                                      │
│   ○  맥락 끊김 → 불안 → 반복전화       │
│      → 보호자 부담                    │
│      = 맥락을 다시 잇는 서비스          │
│                                      │
└──────────────────────────────────────┘
```

- 위쪽(✕)을 먼저 띄우고 **한 박자 뒤** 아래쪽(○)을 띄운다
- 위쪽은 회색으로 죽이고 아래쪽만 살린다
- 이 슬라이드가 이 발표에서 **논리적으로 가장 중요하다.** 여기서 방향 전환이
  안 읽히면 뒤의 모든 기능이 "그냥 AI 말벗"으로 보인다

- 배경: 어두움(감정 구간으로 복귀)

- `"응, 갈게요."` 는 처음엔 따뜻한 색으로 띄웠다가 마지막 줄이 뜰 때
  **회색으로 바뀌게** 한다. 색 하나로 다정함이 해로움으로 뒤집힌다
- 이모지가 자료 톤과 안 맞으면 단색 아이콘으로 대체

- 8개 규칙 중 **4개만** 올린다. 나머지는 백업 슬라이드(B2)
- 마지막 한 줄은 구분선 아래에 따로. 이게 이 슬라이드의 킥이다
- 규칙 8개를 다 보여주고 싶은 유혹을 참는다. 4개는 읽히고 8개는 안 읽힌다

```
┌──────────────────────────────────────┐

│                                      │

│      + 검사 층   [91]%   ← 차이가 핵심  │

```

- **⚠️ 대괄호 숫자는 발표 전 `tools/eval.py`로 재측정해 채운다.**
  22개 시절 값이 그대로 박혀 있으면 질문 하나에 무너진다
- 두 막대를 나란히 그린다. 절대값보다 **차이**가 보이게
- 하단에 아주 작게 한 줄: `모델의 자기 신고값은 믿지 않고 실제 문장을 검사한다`

- 하단 두 줄만 강조색. 위 세 줄은 근거일 뿐이다
- 이 한 장이 "왜 관리형 SFU를 안 썼나"에 대한 답이 된다.
  질문이 들어오면 이 슬라이드로 돌아온다

## 백업 슬라이드 (질문 대비, 발표 중 넘기지 않음)

번호를 B로 붙여 본편 뒤에 둔다. 발표자 노트에 **어떤 질문에 어느 장인지**
적어 둔다. 질문받고 슬라이드를 찾느라 넘기는 모습이 제일 안 좋다.

| 번호 | 내용 | 대응 질문 |
|---|---|---|
| B1 | eval 시나리오 카테고리 분포와 실패 사례 1개 | "그냥 프롬프트 아닌가요?" |
| B2 | 절대 규칙 8개 전문 | "규칙이 몇 개인가요?" |
| B3 | 데이터 처리 경로 — 어떤 데이터가 어디로 가는가 | "음성이 외부로 나가나요?" |
| B4 | 통화 전송 경로 비교표 (A~F 선택지와 탈락 사유) | "왜 LiveKit 안 썼나요?" |
| B5 | 얼굴 연령 파이프라인 (단계별 후보 생성·검증) | "얼굴은 어떻게 만들었나요?" |
| B6 | 리포트 실제 화면 — 관찰층과 마음 기록층 | "가족이 뭘 보나요?" |
| B7 | 8도메인 관찰 분류 (설계 단계임을 명시) | "무엇을 관찰하나요?" |
| B8 | 비용 구조 — 통화당 STT·LLM·TTS·아바타 | "수익 모델은?" |

B3와 B4는 나올 확률이 높다. 이 둘은 만들어 두는 편이 좋다.
