## 작업 0. 먼저 고칠 버그 2개

### 0-1. `meal_uncertain` 오인식 (확인된 버그, 우선순위 최상)

`"아침 약을 먹었나? 약을 먹었는지 기억이 안 난다."` 한 문장이
**식사 불확실과 복약 불확실 양쪽에 잡힌다.** 화면에서 두 항목이 같은
인용문을 달고 나란히 뜨는 이유가 이것이다.

원인 — `backend/analysis/observation_catalog.py`의 패턴:

```
(?:아침|점심|저녁|밥|식사)[^.!?]{0,12}(?:먹었|드셨)[^.!?]{0,14}(?:나|가|모르|까먹)
```

`"아침"`과 `"먹었나"` 사이 12자 안에 `"약을 "`이 들어가서 매칭된다.
`"아침 약"`(복약)을 `"아침 식사"`로 읽는다. CLAUDE.md에 기록된
`"아버지"`가 `"할아버지"`에 걸린 것과 같은 유형이다.

**요구사항**
- `meal_uncertain`에 부정 가드를 추가해 `(?:아침|점심|저녁)\s*약` 형태를 배제
- 반대 방향도 확인: 순수 식사 발화가 `medication_uncertain`에 걸리지 않는지
- **다른 76개 신호도 같은 검사를 한 번 돌릴 것.** 같은 유형의 충돌이 더 있을
  가능성이 높다. 신호 쌍별로 "한 문장이 둘 다에 걸리는가"를 확인하는
  회귀 테스트를 `tests/`에 추가한다
- `tools/observation_scenarios.json`에 이 문장을 음성 사례로 등록

### 0-2. 요일 선택이 동작하지 않음

`요일 × 시간대 통화 밀도` 히트맵에서 현재 선택일(수)만 강조되고 다른 요일을
눌러도 반응이 없다. 요일 셀 또는 행을 누르면 그 날짜로 분석이 갱신되어야 한다.

- 클릭 가능한 요소는 `<button>`으로 만들고 키보드 포커스가 보이게 한다
- 히트맵 셀 자체를 누르면 해당 요일+시간대로 필터되는 것이 이상적이나,
  최소한 요일 행 선택은 동작해야 한다
- 선택 상태는 상단 날짜 입력과 동기화한다

## 작업 1. 종합 현황 가시성 (핵심)

### 1-1. 같은 데이터가 두 번 그려지고 있다 — 하나로 합쳐라

지금 화면에 같은 값이 두 곳에 다른 형태로 나온다.

| 위치 | 형태 | 내용 |
|---|---|---|
| 종합 현황 · `무엇이 달랐는지 먼저 봅니다` | 텍스트 리스트 + 근거 인용 | 식사 +0.4, 복약 +0.4, 외로움 −0.6 |
| 생활 리듬 분석 · `월평균 대비 발화 증감` | 발산형 막대 | 같은 값 + 0.0짜리 3개 |

**요구사항 — 상단 리스트에 발산형 막대를 통합하고, 하단의 중복 막대는 제거한다.**

- 발산형 막대(하단)의 시각적 장점 + 근거 인용(상단)의 정보적 장점을 한 행에 합친다
- 생활 리듬 분석 카드에는 **히트맵만** 남긴다
- 결과 행 구성:

```
식사 불확실                 3회   ░░░░░░│███        +0.4   "아침 약을 …"   상세 ›
월평균 2.6회
```

### 1-2. 정렬 순서를 바꿔라 (지금은 사실상 버그)

현재 **부호 순**으로 정렬돼 있어서 변화량이 큰 항목이 아래로 밀린다.
이전 화면에서 두 번째로 큰 변화였던 `외로움 −5.8`이 맨 아래에 있었다.

**요구사항**
- 1차: 증가 그룹을 변화량 크기순으로
- 2차: 감소 그룹을 변화량 크기순으로 (기본 접힘, 펼치기 가능)
- 변화량 `0.0` 항목은 기본으로 숨기고 "변화 없음 N개"로 접는다.
  지금 하단 막대에 `시간 혼동 0.0`, `물건 위치 0.0`, `그리움 0.0`이
  실제 신호와 같은 공간을 쓰고 있다

### 1-3. 30일 스파크라인 추가

지금 화면에는 "오늘 vs 월평균" **점 두 개 비교**뿐이다. 30일이 어떻게
흘러왔는지가 어디에도 없다. 같은 `+0.4`라도 아래 셋은 의미가 다르다.

```
복약 불확실  3회  +0.4  ▁▂▁▃▂▄▃▅▆█   계속 오르는 중
식사 불확실  3회  +0.4  ▄▂▅▁▃▂▄▁▃▂   그냥 오르내림
물건 위치    3회  +0.4  ▁▁▁▁▁▁▁▂▃█   새로 생긴 것
```

각 행 오른쪽에 12~30점짜리 미니 라인을 넣는다. 축·라벨 없이 선만.

### 1-4. KPI 줄을 stat tile로

```
14통 | 44분 | 26개 발화 신호 | 152.94 개/발화 100건 | 0개 안전 미확인 | 6회 반복
```

- **`152.94`는 거짓 정밀도다.** 소수점 둘째 자리는 의미가 없다.
  정수로 반올림하거나 `발화당 1.5개`로 단위를 바꾼다
- stat tile 표준 구성은 **라벨 + 값 + 증감 + 미니 추세선**인데 지금은
  라벨과 값뿐이다. 각 타일에 전 기간 대비 증감과 스파크라인을 추가한다
- 값과 단위의 타이포 계층을 분리한다 (값은 크고 semibold, 단위·라벨은
  작고 muted)

### 1-5. 하지 말 것

- 오른쪽 **`확인 우선순위` 패널은 지금이 맞다.** 글로 된 행동 지시라
  차트가 필요 없다. 여기에 그래프를 넣지 말 것
- 신호별 증감에 **색 배지를 남발하지 말 것.** 지금은 `+0.4`에도 주황
  배지가 붙어 시선을 뺏는다. Phase 4(관리도)가 들어오면 "평소 범위 밖"일
  때만 색을 칠하게 바꿀 것이므로, 그 전환을 염두에 두고 구현한다

## 작업 2. 디자인 정리

"세련되게"를 아래 규칙으로 번역한다. **취향이 아니라 규칙으로 판단할 것.**

### 2-1. 지금 촌스러워 보이는 구체적 원인

1. **카드 안에 카드가 있다.** 베이지 배경 위 흰 카드, 그 안에 또 테두리
   있는 흰 블록. 표면 단계가 3~4겹이다
2. **모든 카드가 텍스트 3줄로 시작한다.** eyebrow(`월평균 대비 발화 변화`)
   \+ 제목(`무엇이 달랐는지 먼저 봅니다`) + 설명(`항목을 누르면…`).
   화면 상당 부분이 설명문이고 데이터가 밀린다
3. **숫자가 안 도드라진다.** `152.94`와 `개/발화 100건`이 비슷한 크기라
   무엇이 값인지 즉시 안 읽힌다
4. **리스트 행 왼쪽의 색 테두리 막대**는 오래된 패턴이다. 게다가 색이
   무엇을 뜻하는지 범례가 없다
5. **모서리 반경과 간격이 제각각이다.** 탭은 pill, 카드는 큰 라운드,
   칩은 작은 라운드가 섞여 있다

### 2-2. 적용할 규칙

- **표면은 2단계까지.** 페이지 배경 + 카드. 카드 안에 또 테두리 있는
  블록을 만들지 않는다. 필요하면 여백과 구분선으로 나눈다
- **카드 헤더는 제목 1줄, 필요할 때만 설명 1줄.** eyebrow 라벨을 없앤다
- **분리는 테두리가 아니라 여백으로.** 테두리를 쓸 거면 배경보다 한 단계만
  진한 hairline 하나로 통일한다
- **모서리 반경을 하나로 통일**한다(탭 pill만 예외)
- **색은 상태에만 쓴다.** 장식용 색 테두리·색 배경을 제거한다.
  화면에 색이 보이면 "볼 게 있다"는 뜻이 되어야 한다
- **타이포 계층을 3단으로 고정**한다: 값(크게/semibold) · 라벨(작게/기본) ·
  보조설명(작게/muted). 지금은 단계가 너무 많다
- 그림자를 쓸 거면 아주 옅게 하나만. 여러 강도를 섞지 않는다

### 2-3. 절대 어기면 안 되는 접근성 제약

이 앱에는 이미 **글자 크기·선명하게 설정**(`DisplaySettings.jsx`)이 있고,
사용자는 요양원 담당자와 고령 가족이다.

- **"세련됨"을 이유로 대비를 낮추지 말 것.** 본문 텍스트 대비 4.5:1 이상 유지
- **정보 밀도는 낮추되 글자 크기는 줄이지 말 것**
- 기존 글자 크기·명암 설정이 바뀐 화면에서도 그대로 동작해야 한다
- 색만으로 의미를 전달하지 않는다. 증감은 색 + 부호 + 위치로 함께 표시

### 2-4. 차트 공통 규칙 (`docs/analysis_design.md`와 일관되게)

- **이중 축 금지.** "통화 수"와 "신호 건수"를 한 그래프 두 축에 놓지 않는다
- 격자선·축은 실선 hairline. **점선을 격자에 쓰지 않는다**
- 발산형 차트의 **중앙(0)은 반드시 중립 회색**. 중앙에 색조가 있으면
  "변화 없음"이 상태처럼 읽힌다
- 히트맵은 **단일 색조 농담**만 사용(지금 초록 단일 색조는 맞게 하고 있다)
- 시간대 버킷처럼 **묶음 개수는 막대로** 그린다. 선으로 이으면 값이
  연속으로 흐르는 것처럼 오해된다

## 작업 3. 다음 단계 (설계 문서 Phase 순서)

작업 0~2가 끝나면 아래 순서로 진행한다. 순서를 바꾸면 앞 작업이 헛돈다.

### 다음: Phase 4 — 판정 계층
- 4-1. 개인 베이스라인 **관리도**(포아송 `λ̂ ± 2√λ̂`, 과거 N일 기준)
- 4-2. **지속성 판정**(3일 연속 이탈 또는 CUSUM) + 최소 표본 게이트
- 4-3. Mann-Kendall 추세검정

**이게 들어와야 화면이 의미를 갖는다.** 지금은 `+0.4`에도 배지가 붙는데,
2.6회 기준에 +0.4는 거의 확실히 우연이다. 관리도가 있어야 "이 변화를
보여줄지 말지"를 데이터가 판정한다. 완료 후 1-5의 배지를 밴드로 교체한다.

### 그다음: Phase 3 — 발화 구조
`max_run_length`, `return_turns`, MATTR, 대명사 비율.
**현재 Tier B 신호 9개**(`repeated_question`, `pronoun_overuse`,
`perseveration_phrase`, `sundowning_signal` 등)**가 선언만 되고 영구
침묵 상태다.** `backend/care.py:90`이 LLM 신고를 의도적으로 막고 있는데
(설계대로 맞음) 계산기가 없어서 아무것도 채우지 못한다.

### 그다음: Phase 6 — 주입 테스트
Phase 4가 있어야 "며칠째 탐지하는지"를 잴 대상이 생긴다.

### 나머지
Phase 4-4(동시발생 lift) · 4-5(침묵 감지) · 5(통화 내 궤적, 안전 레이어
통계) · 7(코호트 우선순위 화면)
