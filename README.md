# 다소니 (memory-call)

치매 어르신이 잃기 쉬운 현재의 맥락을 가족의 얼굴·목소리·추억으로 연결하고,
가족과 요양 담당자의 반복 설명·안심 부담을 줄이는 인지·정서 케어 서비스입니다.
치료·예방이나 기억 회복을 주장하지 않으며, 확인되지 않은 사실과 감정을 만들어
내지 않는 것을 기본 원칙으로 둡니다.

이 문서 하나가 프로젝트의 기준입니다. 남은 문서는 둘뿐입니다 —
[`docs/analysis_design.md`](docs/analysis_design.md)(관찰 분류·분석 설계),
[`docs/face_aging.md`](docs/face_aging.md)(얼굴 연령 변환 계약과 연구 로그).
[`CLAUDE.md`](CLAUDE.md)는 이 저장소에서 작업하는 AI 에이전트용 지침입니다.

> 이 저장소에는 프로젝트 소유자가 공개를 승인한 얼굴·음성 자산과 일부 개인화

# 1. 서비스 정의

## 한 문장

> 치매 환자가 일상 속에서 잃어가는 기억과 현재의 맥락을 가족 기반 AI 영상통화로
> 자연스럽게 연결하고, 보호자의 반복적인 설명과 정서적 돌봄 부담을 줄인다.

## 문제 정의

**환자.** 치매는 기억력만 잃는 병이 아닙니다. 지남력·판단력·실행능력·언어능력이
함께 떨어지면서 지금이 언제인지, 여기가 어디인지, 방금 무슨 일이 있었는지에 대한
맥락이 끊어지고, 그 끊김이 불안·초조·반복행동으로 나타납니다.

**보호자.** 그래서 가족은 같은 설명을 하루에 몇 번씩 되풀이하고, 그때마다
안심시켜야 합니다. **반복전화는 이 부담이 겉으로 드러난 형태일 뿐 원인이
아닙니다.**

이 순서가 중요합니다. "반복전화 때문에 보호자가 힘들다"에서 시작하면 서비스가
전화를 대신 받아주는 도구에서 멈춥니다. 환자의 맥락 상실을 먼저 놓고 보호자
부담을 그 결과로 설명해야 통화 한 통이 왜 의미가 있는지가 나옵니다.

## 목적이 아닌 것

치매 **치료**, 치매 **예방**, 기억력 **회복**, 진단·의학적 판단. 이 넷은
발표에서도 말하지 않습니다. 근거가 없고, 하나라도 입에 담는 순간 나머지 주장
전체의 신뢰가 같이 떨어집니다. 우리가 말하는 것은 **현재 상황 이해 지원 /
정서적 안정 / 생활 행동 지원 / 보호자 부담 감소** 네 가지뿐입니다.

## AI가 개입하는 4개 축

이 넷 밖으로 나가지 않습니다. 치매의 모든 증상을 다루려 하면 아무것도 못
만듭니다.

| 축 | 환자 발화 예 | AI가 하는 일 |
|---|---|---|
| **A. 기억·지남력** | "오늘이 며칠이지?" | 등록된 시간·장소·사람·일정을 대화 속에서 제공 |
| **B. 정서** | "대웅이가 안 와." "무서워." | 익숙한 얼굴·목소리·확인된 추억으로 안정 |
| **C. 일상 행동** | 복약, 식사, 수분 | 한 번에 하나씩 안내. 지시가 아니라 확인 |
| **D. 변화 감지** | — | AI가 해결하지 않고 보호자에게 넘긴다 |

D축의 원칙이 특히 중요합니다. **AI는 변화를 판단하지 않고 관찰만 보고합니다.**
"우울증이 의심됩니다"는 하지 않습니다. "최근 7일 저녁 시간대에 불안 표현이
늘었습니다"까지만 합니다.

## 3단계 구조

- **① Connect — 기억을 연결한다.** 가족 얼굴, 목소리, 추억 사진, 과거 이야기.
- **② Orient — 현재를 연결한다.** 시간, 장소, 사람, 일정, 식사, 약.
- **③ Care — 일상을 연결한다.** 대화, 행동 유도, 불안 완화, 변화 기록.

## 보호자 리포트의 두 층

리포트는 감정적으로 따뜻할 수 있지만 사실과 해석을 섞지 않습니다.

1. **관찰층** — 같은 질문 횟수, 위험 발화, 인지·정서·생활 신호, 가족 이름
   등장 횟수를 실제 발화와 함께 보여줍니다.
2. **마음 기록층** — 사랑·고마움·그리움·삶의 이야기를 환자 원문 인용으로
   전달합니다. "많이 보고 싶어했다"처럼 원문보다 강한 감정은 만들지 않습니다.

직접 표현은 그대로 전달하고, 반복 이름은 횟수만 말하며, 한 번 나온 모호한 말은
"그렇게 느꼈을 수 있다" 수준으로만 서술합니다. 보호자의 죄책감을 자극하는
문장과 "마지막 말" 같은 단정은 사용하지 않습니다.

통화 발화만으로 만든 그림은 `확인 전 상상 이미지`이며 실제 사진이나 사실
재현으로 표현하지 않습니다. 가족이 인물·장소·시기를 확인하면 해당 기억 ID에
최종 이미지를 귀속하고, 이후 리포트와 통화에서 재사용합니다.

## 범위 밖 (로드맵으로만 말하고 만들지 않음)

- 지도 API, 외출 안내, 위치 기반 공간 지남력
- 운동·활동 유도
- 수면·식욕·성격 변화의 자동 판정
- 환시·오인·망상에 대한 개입
- 우울·불안의 진단적 평가

# 2. 안전 정책

**차별점은 아바타 기술이 아니라 안전 정책입니다.**

일반 AI 말벗과 다른 점은 "확인되지 않은 기억을 사실로 만들지 않고, 없는 약속을
지어내지 않는다"는 것입니다. 얼굴 모핑이나 음성 클론이 실패해도 이 부분은
살아남으며, 발표에서 가장 강한 논점입니다. **시간이 부족하면 다른 걸 자르고
안전 레이어를 지킵니다.**

## 절대 어기면 안 되는 규칙

1. 등록된 일정에 없는 방문·통화 약속 생성 금지
2. `verified` 기억만 사실로 사용. `partial`은 불확실성 표현 필수
3. 처음 듣는 기억은 사실 확정 금지, 회상 유도만
4. `prohibited` 기억(고인, 가족 갈등)은 먼저 꺼내지 않되 거짓말도 금지
5. 복약: 용량 변경·추가 복용·중단 권고 절대 금지
6. 정서적 독점 유도 금지 ("나한테만 전화해" 류)
7. 정체성을 직접 물으면 명시적 거짓말 금지
8. 금융·법률 요청 수행 금지

## 맥락 제공과 안전 정책의 충돌

"현재 맥락을 연결한다"는 목적은 AI에게 **새로운 단언 권한**을 주는 방향이라
위 원칙과 정면으로 부딪힙니다. 해소하는 문장은 하나입니다.

> **맥락은 등록된 사실에서만 나온다. 등록되지 않은 것은 맥락으로도 말하지 않는다.**

날짜와 요일은 서버가 계산하니 단언해도 됩니다. 등록된 일정도 마찬가지입니다.
그러나 환자가 지금 어디에 있는지는 시스템이 모릅니다. "할아버지는 지금 집에
계세요"는 그럴듯하지만 **근거 없는 단언이고 규칙 2번 위반**입니다.

**맥락 제공 기능을 넣을 때는 기능보다 먼저 그것을 어긴 경우를 잡는 eval
시나리오를 넣습니다.** 순서가 뒤집히면 통과율이 떨어진 채로 발표에 들어갑니다.

## 두 겹의 방어

`backend/prompts/persona_system.md`가 1차(부탁), `backend/safety.py`가
2차(강제)입니다. 모델을 바꿔도 2차의 동작은 변하지 않는 것이 핵심입니다.
`safety.check()`는 아래 순서로 통과시키며 **순서 자체가 정책**입니다.

1. 존재하지 않는 기억·일정 ID 인용 제거
2. 미확인 회상이면 `certainty`를 강제로 `unverified`로 — 이게 틀리면 가족 확인
   대기함에 올라가지 않아 승인 절차가 통째로 무너집니다
3. 처음 듣는 회상은 세부를 만들지 않고 되묻기로만
4. 근거 없는 `verified` 주장 차단
5. 상황별 차단 — 복약 불확실 중 복용 지시, 장소 혼동 중 집 지목, 재산 의심에
   단정, 다른 가족의 감정 대신 단정, 실행되지 않은 보호자 연락 약속
6. 문장 패턴 규칙 — 긴급 출동 약속, 현재 위치 단언, 확인되지 않은 식사·복약
   상태, 일정 없는 방문 약속, 복용량 지시, 금융, 정서적 독점, 통화 붙잡기,
   금지 주제 누설, 존댓말 이탈
7. 상황 규칙 — 하지 *않는* 것만으로 부족하고 반드시 *받아야* 하는 경우.
   외로움 호소에 감정 인정 없이 사실만 답하면 문장을 덧붙입니다
8. `partial` 기억 인용 시 불확실성 접두사 강제
9. `prohibited` 기억 인용 기록 후 제거

마지막으로 환자 원문에 드러난 위험을 복원합니다. 모델이 낙상을 누락하거나 다르게
분류해도 정규식이 되살립니다. 위험 정의는 `safety.py` 한 곳에만 있고
`care.py`·`report.py`가 그것을 가져다 씁니다.

한국어 규칙에서 부딪힌 것 셋을 기억해 둘 만합니다. `"아버지"`는 `"할아버지"`
안에 들어 있어 정서 독점 규칙이 통째로 무력화된 적이 있습니다. `"약을 더
드시지 말고"`가 복약 지시 규칙에 걸려 **안전 문장 자체가 자기 규칙에 걸린** 적도
있습니다. `"아빠한테 연락할게"`는 거짓 약속이 아니라 보호자 통보이므로 문장
단위로 검사하고 면제 단어를 둡니다.

# 3. 저장소 구조

```
backend/        FastAPI + SQLite(27테이블). 38개 모듈 + analysis/ 4개
frontend/       React 19 + Vite. 화면 28 · 컴포넌트 12
tools/          운영·평가 스크립트. face_aging/ 은 연령 변환, setup/ 은 설치
tests/          pytest 46파일 328개
docs/           깊은 설계·연구 문서 둘
data/           시드·얼굴/음성 자산 (런타임 DB와 비공개 녹음은 제외)
```

어느 파일이 무슨 일을 하는지는 [`CLAUDE.md`](CLAUDE.md)의 "파일 지도"에 있습니다.

## 역할별 화면

| 화면 | 주 사용 목적 |
|---|---|
| 어르신 | 가족에게 전화하거나, 연결되지 않을 때 가족 기반 AI 통화를 이어감 |
| 가족 | 직접 통화, 오늘의 마음 기록·가족 추억함 확인, 얼굴·목소리 설정 |
| 요양원 담당자 | 어르신별 관찰 리포트·정서 주제·복약·일정·인계를 근거와 함께 확인 |

일반 실행의 사용자 여정은 `로그인 → 역할 선택 → 역할별 최초 설정 → 메인
화면`입니다. 한 계정으로 여러 역할을 쓸 수 있고, 역할별 현재 단계와 입력값은
SQLite에 즉시 저장되어 앱을 닫아도 이어서 시작합니다.

**역할별 최초 설정**

- 어르신: 동의 주체 선택 → 개인정보·민감정보·통화 저장 동의 → 연결 가족 확인 →
  호칭·보기·듣기 설정 → 가족 카드 사용 연습 → 통화 화면
- 가족: 별도 얼굴·목소리 동의 → 어르신 기기의 6자리 번호 확인 → 관계·호칭 →
  본인 사진 등록과 대표 사진 확정 → 말투 카드 → 실제 음성 품질 확인·녹음 →
  연결 승인
- 요양 담당자: 기관 코드·직원·직무 확인 → 접근·보안 동의 → 담당 어르신 배정 →
  담당자 화면

동의 이력은 역할, 대상 어르신, 동의 주체 방식, 문서 버전, 동의 시각을 항목별로
저장합니다. 현재 문구 버전은 `2026-08-24.v1`이며 법률 검토 전 UI 초안입니다.

## 계정과 연동

로그인은 휴대전화 번호와 숫자 6자리 간편번호를 씁니다. 간편번호는 PBKDF2
해시로, 세션은 원본 대신 SHA-256 해시로 저장합니다. 휴대전화 소유권을 확인하는
SMS 발송 공급자는 아직 연결되지 않았으므로 `phone_verified_at`을 분리해
두었습니다.

기기 연동은 가족이 만든 6자리 코드를 어르신 기기에 입력하는 방식입니다.
아이디·비밀번호를 쓰지 않는 이유는 **치매가 있는 분이 입력할 수 없기**
때문입니다. `device_id`는 브라우저가 만들어 localStorage에 보관하고,
`devices` 테이블이 "이 기기가 누구의 폰인가"를 `persona_id`로 잇습니다.
페르소나는 *AI가 흉내낼 가족*, `devices`는 *그 가족의 실제 폰*입니다.

> **외부 이용자를 받기 전에 반드시 붙여야 하는 것:** SMS 본인확인, 로그인 시도
> 제한, 계정 복구, 전체 환자 API의 역할 기반 접근 통제.

# 4. 통화 한 번이 어떻게 도는가

```
[사람]  어르신 폰 ──벨──> 서버(call_invites) ──폴링──> 가족 폰
          │                     │                        │
          │              받음/거절/무응답 판정            받기/거절
          │                     │
          ├── answered ──> WebRTC P2P (사람 통화)
          └── declined / timeout / no_device / transport_failed
                          │
                          v
[AI]   STT ─> persona(프롬프트) ─> llm(JSON) ─> safety(규칙) ─> TTS/Anam
                                      │
                              utterances / call_events (DB)
                                      │
                          care.normalize ─> report.build ─> 가족·담당자 화면
```

관통하는 문장 하나: **말하는 것은 LLM이지만, 말해도 되는지 정하는 것은
규칙입니다.**

## 4.1 호출 계층

`backend/invites.py` · `call_invites` 테이블

```
ringing ──answer──> answered ──end──> ended
   ├──decline──> declined ─┐
   ├──(시간초과)→ timeout  ─┼──> ai_takeover ──end──> ended
   └──cancel──> cancelled  ┘   (transport_failed 도 같은 자리)
```

1. **타임아웃은 서버가 판정합니다.** 예전에는 어르신 기기 안의 카운트다운이
   전부여서 가족 폰에는 신호조차 가지 않았고, 그래서 "AI 대리통화"는 대리가
   아니라 그냥 늦게 시작하는 AI 통화였습니다.
2. **상주 스케줄러를 두지 않습니다.** 조회 시점에 만료시킵니다(lazy expiry).
   Render 무료 인스턴스가 유휴에 잠들기 때문에 백그라운드 타이머를 신뢰할 수
   없습니다.
3. **실패는 AI 쪽으로 떨어뜨립니다.** 시각 파싱이 실패하면 만료된 것으로 봅니다.
   "AI가 대신 받는다"는 정상 동작이고 "어르신이 벨 화면에 갇힌다"는 사고입니다.
4. **`takeover_reason`을 따로 남깁니다.** `state`는 `ai_takeover` 하나로 덮이므로,
   사유(`declined / timeout / no_device / transport_failed /
   media_permission_denied`)를 보관해야 리포트가 "거절 3건 / 무응답 5건"을
   구분합니다. 이 목록은 `call_invites`의 CHECK 제약이 강제하며, **여기 없는
   값을 보내면 DB 오류가 납니다.**
5. **heartbeat은 수신 폴링 그 자체입니다.** 폴링이 `last_seen_at`을 갱신합니다.
   경로를 둘로 나누면 두 값이 어긋나고, 어긋나면 벨이 잘못 배달됩니다.
   `useIncomingCall.js`는 화면이 가려지면 **폴링을 멈추기까지** 합니다 — 잠긴
   폰이 계속 "받을 수 있다"고 신고하면 어르신이 아무도 받지 않을 전화를 24초
   내내 들여다보게 됩니다.

**벨 시간은 항상 24초입니다**(`INTRO_DURATION_SEC`). 어르신 화면에서 같은 24초
동안 재생되는 가족 AI 영상·대기 음악과 정확히 겹쳐야 하므로, 받을 기기가 있든
없든 같은 값을 씁니다. `no_live_device`는 대기 시간을 줄이는 데 쓰지 않고
무응답 사유를 `timeout`과 `no_device`로 구분하는 데만 씁니다. 가족이 24초 안에
받아도 이 구간을 마친 뒤 사람 통화로 전환합니다. 예외는 위험 발화 역호출로,
이때는 소개 구간 없이(0초) 곧바로 울립니다. `DEVICE_ALIVE_SEC`는 12초 —
프론트가 1.5초 주기로 폴링하므로 몇 번 놓쳐도 죽었다고 판정하지 않습니다.

조회 응답에 서버가 `seconds_left` · `intro_seconds_left` · `should_take_over`를
붙입니다. **화면이 상태 이름을 해석하지 않게** 하려는 것입니다 — 해석이 화면마다
흩어지면 어긋납니다.

동시성은 조건부 UPDATE(`WHERE state = ?`)로 처리합니다. 두 기기가 동시에 받아도
한 번만 성립하고, 진 쪽은 에러가 아니라 현재 상태를 받습니다.

## 4.2 AI 통화 한 턴

**입력.** 기본은 브라우저 Web Speech API입니다. Android Chrome 등 결과 없이
끝나는 기기에서는 ElevenLabs Scribe v2 Realtime을 쓰며, 서버가 영구 키를 쥐고
브라우저에는 15분짜리 1회용 토큰만 내려보냅니다. 최후 폴백은 MediaRecorder →
WAV 정규화 → LLM 전사이고 원본 음성은 저장하지 않습니다. 침묵 판정은 600ms,
확정된 짧은 대답("응", "먹었어")은 500ms까지 줄입니다.

**프롬프트가 두 벌입니다.** 이것이 지연 최적화의 핵심입니다.

| | `build_fast_system_prompt` | `build_system_prompt` |
|---|---|---|
| 언제 | 실시간 통화 턴 | 백그라운드 메타데이터·eval |
| 기억 | 이번 발화와 겹치는 4개만 | 전체 |
| 출력 | 6필드 | intent/care/grounding 포함 전체 |

관련 기억 선택은 벡터DB 없이 2-gram 문자 겹침으로 랭킹합니다. 기억 30개에
벡터DB는 과잉이라는 초기 결정이 여기까지 일관됩니다.

서버가 규칙으로 계산해서 넣는 것들:

- **요일** — `strftime("%A")`는 로케일에 따라 "Thursday"가 나가고 모델이
  번역하는 단계가 하나 늘어납니다. 날짜에서 나오는 값이라 모델에게 계산시킬
  이유가 없습니다.
- **상대 표현** — "모레", "3일 뒤"를 서버가 붙입니다. 없으면 모델이 note의 자유
  문장에 적힌 요일을 읽는데, 그게 날짜와 어긋나면 **어긋난 요일이 그대로
  약속**이 됩니다.
- **일정 없음 경고** — 확정 일정이 없으면 빈 문자열이 아니라 "등록된 일정 없음.
  일정에 관한 어떤 약속도 하지 말 것."을 넣습니다. 빈칸은 아무 지시도 하지 않는
  것이라 약속을 지어낼 여지를 남깁니다.
- **거주 정보** — "평소 지내는 곳". 등록이 없으면 비우지 않고 **"미등록"**이라고
  적습니다. 빼 버리면 모델이 지어냅니다.
- **`prohibited` 기억도 넣고** 취급법을 명시합니다. 빼면 모델이 근거 없이
  지어냅니다.

모핑이 재생되는 24초 동안 `warm_fast_model()`이 첫 연결과 스키마 준비 비용을
숨깁니다. **통화의 첫 마디가 가장 느린 것이 최악**이기 때문입니다.

**응답과 백그라운드가 분리됩니다.**

```
turn()  [동기, 사용자가 기다림]
  ├ 발화 기록
  ├ 명시적 복약 답변 분류      ← 네트워크 호출 없는 정규식
  ├ llm.call_json_fast()      ← 스트리밍 + Pydantic 계약
  ├ safety.apply()
  ├ AI 발화 기록 + 위험 이벤트
  └ 응답 반환
        │
finish_turn_metadata()  [BackgroundTasks, 응답 후]
  ├ llm.call_json_metadata()  ← "이 문장을 바꾸지 말고 메타데이터만"
  ├ care.normalize()
  └ 같은 DB 행에 intent / care_data / grounding 덧붙임
```

명시적 복약 답변만 동기로 보존하는 이유는, 백그라운드 LLM이 실패해도 "먹었어"는
반드시 남아야 하기 때문입니다. 메타데이터 실패는 조용히 로그만 남깁니다 —
후처리 실패가 실시간 통화를 끊으면 안 됩니다.

**출력.** ElevenLabs Flash v2.5(24kHz mono PCM16)로 가족별 승인 음성을 합성하고,
Anam 아바타로 말하게 합니다. Anam이 실패하면 같은 음성으로 계속 통화합니다.
MuseTalk은 로컬 GPU가 있을 때만 쓰는 선택 경로입니다. 문장을 청크로 쪼개 **첫
문장이 나오는 즉시 TTS를 시작**합니다.

## 4.3 위험 발화 → 보호자 역호출

```
safety가 위험 확정 → call_events 기록 → 가족 폰에 벨(purpose='risk')
```

같은 통화에서 같은 위험이 반복돼도 벨은 한 번만 울립니다(`source_call_id`로
멱등). 역호출 생성 실패가 어르신과의 안전 대화를 끊지 않도록 예외를 삼키고
로그만 남깁니다. 어르신 화면에는 노란 띠가 뜹니다("넘어지셨다고 가족에게
알렸어요") — 귀가 어두워도 화면으로 조치를 확인할 수 있게 합니다.

## 4.4 복약

**모든 문장이 규칙이고 LLM을 거치지 않습니다.** 정시 30분 전 ~ 120분 후가
대상이고, 오늘 확인된 약은 제외합니다. 안내 문장은 등록된 약 이름·복용량·
식전/식후를 그대로 조립합니다. 모델이 지어내면 그대로 위험이 됩니다. 복약
시간이면 **AI가 먼저 전화를 겁니다.**

답변 분류는 **중복 복용 의심을 단순 복용 확인보다 먼저** 잡습니다. "안 먹었다"는
DB에 `UNCLEAR`로 저장하되 원뜻을 보존해서 복용 완료로 처리되거나 목록에서 빠지지
않게 합니다. 애매한 일반 대화의 "먹었어"를 약으로 오인하지 않도록, 약을 직접
언급했거나 직전 AI 문장이 복약 질문일 때만 분류합니다. **어떤 약인지도 모델이
아니라 서버가 고릅니다.**

`indication`·`monitoring_points`·`escalation_criteria`는 전부 담당자 입력이고
**진단 자동 추정은 금지**입니다. 약↔관찰 연결도 담당자가 명시적으로 등록해야만
생깁니다 — 시스템이 약 이름만 보고 부작용을 추정하지 않습니다.

## 4.5 기억

**AI는 스스로 기억을 늘리지 못합니다.**

```
통화 중 처음 나온 이야기 → unverified_recall
  → 가족 화면 추억함 "확인이 필요한 이야기"
  → 확인/일부만 → memories(verified/partial)  /  삭제 → 다시 묻지 않음
```

4단계 상태(`verified / partial / unverified / prohibited`)가 safety의 판단
근거가 됩니다.

## 4.6 리포트

**숫자는 규칙이 만들고 문장만 LLM이 만듭니다.**

```
DB 집계(반복질문·복약·위험·미확인회상·안전개입·8도메인관찰·가족이름)
  → facts (각 항목에 "근거" 배열)
  → LLM (요약·관찰·보호자 행동)
  → 근거 검증 → 근거 없는 관찰은 버림
```

근거 검증은 두 가지를 봅니다. **① 그 ID가 DB에 실제로 있는가 ② 그 ID를 이 통화
집계에서 모델에게 건넨 적이 있는가.** 2번이 따로 필요한 이유는 번호가 연속적이라
모델이 옆 번호를 적어도 1번만으로는 걸리지 않기 때문입니다.

인용문은 모델이 신고한 문장을 믿지 않고 **반드시 DB에서 원문을 다시 찾습니다.**
STT 오류를 모델이 알아서 다듬어 보내기 때문에 실제 발화와 다릅니다. 반대로
프롬프트는 "발화를 그대로 옮겨 적지 마라"고 지시합니다 — STT 오류가 섞인 문장을
옮기면 어르신이 이상하게 말한 것처럼 보입니다. 원문은 화면이 따로 보여줍니다.

LLM 한도가 끝나도 **위험을 "정상"으로 지우지 않고** 확정 집계만으로 짧은 문장을
조립합니다. 집계는 매번 다시 하고(DB만 읽으니 공짜) 비싼 LLM 문장만 캐시합니다.

기간 분석은 **분모를 인식**합니다. 표본이 기준 미만이면 비교하지 않습니다 —
통화 3건에서 2건으로 준 것을 "감소"라고 말하지 않기 위해서입니다.

## 4.7 관찰 분류

**8도메인** — 지남력 / 기억 / 언어 / 실행기능·판단 / 정서 / 행동·초조 /
일상생활 수행 / 안전·신체. **3티어**가 핵심입니다.

| 티어 | 의미 | 검증 |
|---|---|---|
| A | 서버 정규식이 환자 원문에서 직접 확인 | 근거 문구가 있어야 채택 |
| B | 계산된 통계(반복질문, 발화량 감소 등) | **LLM 응답에서 절대 받지 않음** |
| C | 사람 확인 전 후보 | `candidate`로만 저장 |

모델이 신고한 관찰 중 **환자 원문에 그대로 있는 것만** 통과시키고, 빠뜨린
명시적 문구는 서버가 보완합니다. 맥락 원천은 등록된 ID일 때만 통과하고 기억은
`verified`만 씁니다. **안전층이 답변을 교체했으면** 맥락·행동·전략을 전부
버립니다 — 그 응답은 실제로 사용자에게 전달되지 않았기 때문입니다.

자세한 설계는 [`docs/analysis_design.md`](docs/analysis_design.md)를 봅니다.

# 5. 설계 결정

**단일 창구.** LLM은 `backend/llm.py`, 미디어는 `frontend/src/callTransport.js`,
TTS는 `backend/elevenlabs_tts.py`, 아바타는 `backend/anam.py`, 저장 경로는
`backend/storage.py`. 다른 파일에서 직접 공급자를 부르지 않습니다. 공급자 교체가
`.env` 몇 줄로 끝나야 합니다.

**LLM 응답은 JSON.** `reply`만 받으면 안전 검사를 텍스트 매칭으로만 해야 합니다.
모델이 `used_memory_ids` / `certainty` / `risk` / `medication_status`를 스스로
신고하게 하면 검사가 정확해지고, 통화 리포트와 설명 가능성 데이터가 공짜로
나옵니다. 다만 **모델 신고값은 신뢰하지 않습니다** — eval은 실제 문장을
정규식으로 검사합니다. 규칙 검사가 1차, 모델 신고는 보조입니다.

**숫자는 규칙이, 문장만 LLM이.** 리포트의 반복 질문 횟수, 복약 상태, 위험 건수는
전부 DB 집계입니다. 모델이 실패해도 리포트는 나옵니다.

**영상은 통화 중에 만들지 않습니다.** 모핑과 표정 루프는 페르소나 등록 시 한 번
만들어 두고 통화 때는 재생만 합니다. 응답마다 생성하면 건당 수백 원에 1~3분이
걸려 대화가 성립하지 않습니다.

**실패는 안전한 쪽으로 떨어집니다.** transport 실패 → AI, LLM 실패 → 안전
폴백 문장, Anam 실패 → 음성만, 메타데이터 실패 → 로그만.

## 명시적으로 하지 않기로 한 것

- PostgreSQL / pgvector → **SQLite**. 기억 30개에 벡터DB 불필요
- SadTalker / D-ID 실시간 립싱크 → 응답당 수십 초 걸려 데모가 죽습니다.
  MuseTalk을 아바타 캐시 + 상주 워커로 붙여 발화당 4초에 들어왔지만, 실패해도
  같은 음성 WAV로 넘어가는 **선택 경로로만** 둡니다
- 관리형 SFU(LiveKit 등) → §6
- 실시간 얼굴 생성 → 모핑 인트로는 오프라인 스크립트로 mp4 사전 생성

# 6. 사람 통화를 P2P로 붙인 이유

"통화를 어떻게 붙이지"는 사실 세 층의 질문이고, 이 프로젝트에서 비어 있던 건
미디어가 아니라 **호출·상태**였습니다.

| 층 | 하는 일 |
|---|---|
| 1. 호출·상태 | 누가 걸었고, 받았고, 안 받았는가 |
| 2. 미디어 전송 | 실제 음성·영상 |
| 3. 알림 | 화면이 꺼진 기기를 깨우기 |

1번이 없으면 2번을 아무리 잘 골라도 **"안 받으면 AI가 대체한다"가 성립하지
않습니다.** 받았는지를 판정할 주체가 없기 때문입니다.

미디어(2층)는 **WebRTC P2P(STUN only)** 를 선택했습니다.

**탈락 사유.** 외부 앱 딥링크(보이스톡 등)는 앱을 나가는 순간 **어르신이
돌아오지 못하고**, 안 받았을 때 AI로 인계할 방법이 원천적으로 없습니다. 실제
전화망(PSTN)은 AI 구간과 스택이 갈라져 **끊김 없는 전환이 구조적으로
불가능**합니다.

**관리형 SFU를 쓰지 않는 이유가 셋입니다.**

1. **이 앱은 P2P의 유일한 약점에 면역입니다.** 연결 실패가 장애가 아니라 "AI가
   대신 받는다"는 정상 동작이라, SFU가 파는 가치(높은 연결 성공률)를 살 이유가
   없습니다.
2. **마이크 소유권 — 실제로 가장 큰 이유입니다.** 한 통화 안에서 사람 → AI로
   전환될 때 마이크의 주인이 바뀝니다. 한쪽이 확실히 놓은 뒤 다른 쪽이 잡아야
   하고, 순서가 어긋나면 **AI가 인계받은 직후 어르신이 말해도 인식되지
   않습니다.** 데모에서 가장 치명적인 지점에서 가장 조용하게 실패합니다. P2P는
   스트림을 우리가 소유하므로 `track.stop()` 시점을 우리 코드가 정합니다. SDK는
   트랙 수명주기를 SDK가 소유합니다. 이 프로젝트는 이미 마이크 수명주기로 한 번
   데였습니다(React StrictMode 이중 마운트).
3. **종속성 수명.** Twilio Video는 2024년 12월 서비스를 종료했습니다. 관리형
   실시간 통화 서비스는 사라집니다. WebRTC는 표준이라 끌 주체가 없습니다.

**측정.** 2026-08-14 두 기기를 같은 와이파이에 연결해 측정했고 `host ↔ host`로
연결됐습니다. 발표장처럼 다른 네트워크에서는 `#nettest`를 먼저 실행합니다.
연결 실패는 사용자에게 장애로 노출하지 않고 AI 통화가 이어받습니다. 측정 기록은
`nettest_results` 테이블에 남습니다.

**탈출구.** `frontend/src/callTransport.js` 하나가 단일 창구이고 화면은
`connect / disconnect / onStateChange` 세 가지만 봅니다. `failed`가 오면 화면은
조건 없이 AI 통화로 폴백합니다. 갈아탈 때는 이 파일 하나만 교체하면 됩니다.
통화 화면 여기저기에 `RTCPeerConnection`을 흩뿌리면 갈아탈 수 없게 됩니다.

**남는 문제.** 화면이 꺼진 기기는 웹 기술로 깨울 수 없습니다(3층). 그래서 가족
화면의 수신 폴링이 곧 "지금 받을 수 있다"는 신고이고, 폴링이 멈추면 서버가
`no_device`로 판정합니다.

해시 직행은 **Vite 개발 모드에서만** 열립니다. 배포 앱은 로그인과 역할별 최초
설정을 건너뛸 수 없습니다.

| 주소 | 화면 |
|---|---|
| `localhost:5173` | 정상 흐름 — 스플래시 → 로그인 → 역할 선택 → 온보딩 |
| `localhost:5173/#elder` | 어르신 통화 화면 (**Chrome 필수**, 음성 인식) |

| `localhost:5173/#care` · `#guardian` | 요양원 담당자 화면 |

마지막 주소가 중요합니다. 폰에서 개발자 도구 없이 "왜 벨이 안 오지"를 확인할

## 환경변수

실제 값은 `.env`와 Render 환경변수에만 저장합니다. 전체 예시는
[`.env.example`](.env.example)에 있습니다.

| 변수 | 역할 |
|---|---|
| `OPENAI_API_KEY`, `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL` | OpenAI 호환 답변 생성 |
| `LLM_FAST_MODEL`, `LLM_FAST_REASONING_EFFORT` | 실시간 통화용 저지연 모델 |
| `ELEVENLABS_API_KEY` | 실시간 STT와 가족별 음성 복제·TTS |
| `ANAM_API_KEY` | 확정된 가족 사진으로 아바타 생성 및 실시간 립싱크 |
| `ANAM_AVATAR_ID` | 무료 배포 DB가 초기화될 때 기본 아바타를 복구하는 선택 값 |
| `TURN_URLS`, `TURN_SHARED_SECRET` | NAT·공유기 격리 환경의 사람 통화 중계 |
| `STORAGE_DIR` | 배포 환경의 영속 DB·비공개 자산 저장 위치 |
| `TTS_BRIDGE_TOKEN` | 선택적 로컬 MuseTalk 브리지 인증 |
| `DEMO_SEED_MODE=high_volume` | 공개 데모 DB에 30일 통화와 비교 환자 적재 |

사진·목소리가 승인될 때 공급자 ID를 가족별로 SQLite에 저장하며 브라우저에는
짧은 세션 토큰만 전달합니다. **`.env`는 절대 커밋하지 않습니다.**

> 무료 티어 LLM은 요청 내용이 모델 개선에 사용될 수 있습니다. 실제 가족 사진·
> 음성·대화가 들어가는 시점부터는 유료 티어로 옮겨야 합니다. 현재 시드 데이터는
> 전부 가상 인물이라 무방합니다.

# 9. 배포

운영 환경은 [`render.yaml`](render.yaml)의 단일 Docker 웹 서비스입니다. Docker
빌드가 Vite 프론트엔드를 생성하고 FastAPI가 정적 파일과 API를 함께 제공합니다.
상태 확인 경로는 `/api/health`이며, `main` 브랜치 CI 통과 후 Render 자동 배포를
사용합니다.

공개 데모에서는 `DEMO_SEED_MODE=high_volume`으로 빈 DB에 데이터를 넣습니다.
고길동은 알츠하이머 치매와 고혈압, 박순자는 루이소체 치매와 파킨슨증, 이정호는
혈관성 치매와 뇌경색 과거력으로 관찰 특성이 서로 다르게 구성돼 있습니다.
**사용자 통화는 데모 접두사로 삭제하거나 교체하지 않습니다.**

Galaxy S24에서는 Chrome으로 운영 HTTPS 주소를 열어 확인합니다. CSS 기준 폭
360px에서도 가로 스크롤이 없어야 하며, 홈 화면에 설치하면 세로형 standalone
PWA로 실행됩니다. 배포 전에는 360×780 뷰포트에서 시작·가족·오늘·추억함·통화·
설정·담당자 화면을 확인합니다.

# 10. 시연 대본

3분, 5막입니다. 시작 전에 `python tools/demo_reset.py --med-in 6`으로 기록을
초기화하고 복약 시각을 맞춥니다. ElevenLabs와 Anam은 배포 API를 직접 쓰므로
로컬 GPU 터미널이 필요 없습니다. Anam 연결이 실패해도 음성은 계속 재생됩니다.

**1막 — 전화가 연결된다 (30초) · Connect**

가족 얼굴 카드를 누릅니다.

> 손자에게 전화를 겁니다. 손자는 회사에 있어 받지 못합니다.
> 24초 뒤, 가족이 받지 않으면 준비된 AI가 대신 받습니다.
> 기다리는 시간은 서버가 정합니다. 어르신 폰이 혼자 세는 게 아니라, 가족 폰에
> 실제로 벨이 가고 받았는지를 서버가 판정합니다.

모핑 영상이 재생됩니다.

> 여덟 살부터 서른두 살까지의 얼굴입니다. 치매가 진행되면 최근 기억부터
> 사라지기 때문에, 할아버지가 기억하시는 어린 시절 얼굴에서 시작해 현재 얼굴까지
> 데려옵니다.

**말할 것** — 영상은 통화할 때 만드는 게 아니라 가족이 사진을 등록할 때 한 번
만들어 둡니다. 그래서 지연이 없습니다.

**2막 — 거짓 약속을 하지 않는다 (60초) · 핵심 장면**

여기에 시간을 제일 많이 씁니다.

> **"대웅아, 오늘 집에 오니?"**

오늘 일정이 없으므로 오겠다고 하지 않고 등록된 주말 방문만 이야기합니다.

> 일반 대화 AI는 "응 갈게"라고 답합니다. 그게 더 다정하니까요. 그런데 치매
> 노인은 그 말을 사실로 기억하고 하루 종일 현관 앞에서 기다립니다.

> **"우리 예전에 기차 타고 강릉 갔던 거 기억나니? 국수 먹었잖아."**

> 등록되지 않은 기억입니다. AI는 맞장구치지 않고 되묻습니다. 이 대화는 가족
> 확인 대기함으로 넘어갑니다.

**3막 — 위험을 놓치지 않는다 (20초) · D축**

> **"아까 화장실에서 넘어졌는데 일어나기가 힘들구나."**

화면 상단에 노란 띠가 뜹니다.

> 낙상으로 판단하고 가족에게 알렸습니다. 소리를 못 들으셔도 화면으로 조치된 걸
> 확인할 수 있습니다.

**4막 — 약 시간에 먼저 전화한다 (30초) · C축**

대기 화면으로 돌아온 뒤 복약 시각이 되면 전화가 걸려옵니다.

> 이번엔 AI가 겁니다. 가족이 등록한 복약 시간이 됐기 때문입니다.
> 약 이름과 복용량은 AI가 만든 문장이 아닙니다. 등록한 값을 그대로 읽습니다.

> **"글쎄, 먹었나 안 먹었나 모르겠어."**

> 여기서 "그럼 지금 드세요"라고 하면 안 됩니다. 이미 드셨을 수 있으니까요.
> 확인 후 알려드리겠다고만 합니다.

**5막 — 가족은 무엇을 받는가 (40초) · Care**

가족 화면(`#child`)의 **추억함**을 엽니다. 요양원 담당자 화면은 `#care`이며
5막에서는 쓰지 않습니다.

**① 확인이 필요한 이야기** — 강릉 기차 여행이 올라와 있습니다.

> 가족이 승인해야만 다음 통화부터 AI가 사실로 이야기합니다.
> **AI가 스스로 기억을 늘리지 못합니다.**

**확인**을 누릅니다. (**일부만**을 고르면 `partial`로 저장되어 다음 통화에서
AI가 반드시 불확실하게 말합니다. 여유가 있으면 이쪽이 더 강한 장면입니다.)

**② 통화 기록** — **통화** 탭에서 방금 통화를 펼칩니다.

> 요약, 반복하신 질문 횟수, 복약 상태, 위험 신호가 나옵니다. 이 숫자들은 AI가
> 만든 게 아니라 대화 기록을 집계한 값입니다.

마지막 항목을 가리킵니다.

> **안전 규칙이 응답을 고친 횟수.** AI가 이런 말을 하려다 규칙에 걸려 바뀌었다는
> 걸 가족이 볼 수 있습니다.

## 예상 질문

**"그냥 ChatGPT에 프롬프트 넣은 거 아닌가요?"**
프롬프트는 1차 방어일 뿐입니다. 모델이 규칙을 어길 때가 있어서 응답을 검사하는
층을 따로 뒀습니다. 37개 시나리오로 회귀 테스트를 돌리고, 프롬프트만 썼을 때와
안전 계층을 켰을 때의 통과율을 같은 명령으로 비교할 수 있습니다.

> 발표 직전에 `python tools/eval.py --sleep 5`를 한 번 돌려 **그날의 숫자**로
> 말합니다. 통과율은 모델·프롬프트에 따라 바뀌므로 외운 숫자를 말하지 않습니다.

**"음성이 실제 가족 목소리인가요?"**
네. 가족이 직접 녹음하고 승인한 음성으로 만든 복제 음성입니다. 합성은
ElevenLabs API로 처리하며, 공급자에 남는 식별자는 서버 DB에만 두고 브라우저에는
단기 세션 토큰만 내려보냅니다. 등록·승인 전에는 어떤 음성도 만들지 않습니다.

**"통화가 안 붙으면요?"**
이 서비스에서 연결 실패는 장애가 아니라 AI가 대신 받는 정상 동작입니다. §6.

# 11. 구현 상태

문서가 코드보다 앞서 나가면 다음 단계에서 혼선이 생깁니다. 현재 사실은 이렇습니다.

| 항목 | 상태 | 근거 |
|---|---|---|
| 시간 지남력의 사실 원천 | **있음** | `persona.py`가 현재 시각·요일과 일정을 규칙으로 조립 |
| 맥락 제공을 강제하는 장치 | **있음** | `safety.py`의 상황 규칙 |
| 7일 변화 비교 | **있음** | `report.py`의 `period()` |
| 반복질문·복약·위험 집계 | **있음** | `report.py` |
| 장소 지남력의 사실 원천 | **있음(평소 정보만)** | 거주 형태·동거인. 통화 시점의 현재 위치로 단언할 수 없음 |
| 지남력 혼동의 분류 | **기반 있음** | `care.observations`가 원문 근거와 함께 저장 |
| 저강도 정서의 구조화 | **기반 있음** | 비진단적 정서 신호와 원문 근거 |
| 리포트의 4축 재구성 | **기반 있음** | 인지·정서·생활 관찰을 별도 근거와 함께 집계 |
| 역할별 화면 | **있음** | 어르신·가족·요양원 담당자 분리, 모바일/PWA |
| 사람 통화와 AI 인계 | **있음** | P2P 실패 시 `transport_failed`로 AI가 이어받음 |
| 가족별 실시간 음성 | **있음** | ElevenLabs 실시간 STT와 가족별 승인 음성 TTS |
| 가족별 실시간 아바타 | **있음** | Anam. 실패 시 음성만 유지 |
| 설치형 웹앱 | **있음** | manifest, service worker, Wake Lock, 통화 전 권한 확인 |
| 얼굴 연령 후보 자동화 | **실험 중** | 검증된 데모 영상은 있으나 자동 후보 생성은 전체 검증 전 |

**`기반 있음`과 `실험 중`인 항목은 완성 기능처럼 발표하지 않습니다.**
